# 1. Purpose

S0.5-C implements and verifies the public observation projection boundary
between the internal deterministic synthetic world and the information
legitimately available to UNKNOWN.

The purpose of this stage is to ensure that internal simulation state is not
automatically equivalent to public observation state.

The implementation establishes an explicit projection:

```text
WorldState
    |
    v
PublicObservationProjector
    |
    v
PublicObservation
```

The public runtime consumes the deterministic world through this boundary
rather than exposing internal world state directly.

---

# 2. Scientific Role

The observation interface is part of the scientific information boundary.

If UNKNOWN is allowed to observe information that would only exist inside
the simulator or evaluator, later experiments could incorrectly classify an
information-unavailable or representation-failure condition.

Therefore the observation projection must be explicit and testable.

S0.5-C establishes the engineering mechanism required to enforce that
boundary.

It does not establish that the resulting observation interface is sufficient
for the eventual research question.

---

# 3. Research Boundary

The current research boundary is:

> Explicit representation-level inadequacy detection followed by
> failure-triggered representation extension and experimental validation of
> the resulting representation as a reusable abstraction.

S0.5-C addresses only the environment observation boundary required to
experimentally investigate that question.

It does not implement the autonomous discovery loop.

# 5. Runtime Integration

The public runtime now follows this architecture:

```text
PublicEnvironmentRuntime
        |
        v
DeterministicWorld
        |
        v
WorldState
        |
        v
PublicObservationProjector
        |
        v
PublicObservation
```

The runtime operations are:

```text
reset(config, seed)
observe()
step(action)
intervene(intervention)
is_terminal()
episode_metadata()
```

`reset`, `observe`, and `step` use the observation projector when producing
public observations.

The runtime does not return `WorldState` through the public API.

# 6. Public Observation Contract

The public observation currently permits:

* opaque entity identifiers;
* position;
* velocity;
* explicitly permitted relations;
* events;
* observation kind;
* step index;
* deterministic simulation timestamp;
* controlled public attributes.

The public schema remains:

```text
unknown.environment.schemas.public
```

---

# 7. Private Internal State

The deterministic world contains internal state that is not automatically
projected into public observations.

In particular:

* mass remains internal;
* semantic entity category remains internal under the current contract;
* internal world-state structure remains internal;
* evaluator-side truth remains outside the runtime;
* hidden benchmark truth remains outside the public observation layer.

A future scientific contract may deliberately promote additional information
to PUBLIC, but such promotion must be explicit.

---

# 8. Controlled Public Attributes

`PublicEntity.attributes` is not populated by blindly copying the internal
entity object.

Public attributes must come from an explicit allowlisted mapping.

This prevents future additions to internal world state from silently becoming
public observations.

This is a deliberate scientific boundary decision.

---

# 9. Derived Quantities

The projector does not automatically inject derived quantities such as:

* distance;
* relative position;
* relative velocity;
* speed;
* acceleration;
* nearest entity;
* collision probability.

These quantities may be computable from public observations, but they are not
treated as primitive observations merely because the simulator can calculate
them internally.

This preserves a clear distinction between raw permitted information and
future representation-derived quantities.

---

# 10. Observation Identifiers

Observation identifiers are opaque.

They must not encode:

* hidden condition labels;
* ground-truth representation identifiers;
* benchmark condition types;
* semantic world properties.

Identifiers are deterministic rather than random or wall-clock generated.

---

# 11. Entity Ordering

Public entities and relations use deterministic ordering.

Ordering must not depend on:

* hidden benchmark condition;
* evaluator labels;
* hidden causal structure;
* random ordering;
* process timing.

Deterministic ordering supports reproducibility and prevents accidental
semantic leakage through collection order.

---

# 12. Timestamp Semantics

The public timestamp represents deterministic simulation time.

It is not wall-clock time.

This prevents runtime timing from becoming an unintended information channel
and makes deterministic replay possible.

---

# 13. Projection Purity

The observation projector is designed as a projection layer rather than a
second simulation mechanism.

Projection must not:

* mutate world state;
* update hidden state;
* update evaluator state;
* call external services;
* access network resources;
* generate benchmark labels;
* calculate evaluator scores.

---

# 14. Hidden-State Isolation

The public observation implementation does not import the hidden benchmark
schema module.

It does not import the evaluation schema module.

The public runtime similarly does not directly import hidden or evaluation
schema modules.

This maintains the public/hidden/evaluation architecture established during
S0.4.

---

# 15. Runtime Boundary

The public runtime owns only public-facing runtime control state and the
internal deterministic world/projector dependencies required to operate the
environment.

It must not store:

* hidden benchmark truth;
* ground-truth representations;
* benchmark condition labels;
* evaluation records;
* oracle results;
* evaluation scores.

Automated leakage tests verify the current boundary.

---

# 16. Intervention Boundary

The public runtime validates interventions against the public configuration.

The deterministic world does not yet provide intervention transition
semantics.

Therefore `PublicEnvironmentRuntime.intervene()` does not invent a second
transition mechanism.

After public validation, the method explicitly reports that intervention
transition dynamics are not yet implemented.

This is intentional.

The eventual intervention implementation must have a single authoritative
transition source rather than duplicated runtime and dynamics semantics.

---

# 17. Leakage Threat Model

S0.5-C preserves the leakage controls established by S0.4.

Potential leakage channels considered include:

* schema fields;
* runtime attributes;
* imports;
* type annotations;
* serialization;
* identifiers;
* ordering;
* timestamps;
* metadata;
* error messages;
* hidden condition names;
* evaluator information;
* oracle information;
* external dependencies.

The current implementation specifically tests several of these channels.

A complete dynamic leakage audit remains necessary after final benchmark
dynamics exist.
