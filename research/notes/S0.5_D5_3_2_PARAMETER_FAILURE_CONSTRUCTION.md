# S0.5-D.5.3.2 — P1 Parameter-Failure Construction

## Status

Research/design specification.

This document defines the controlled construction of P1 parameter-failure
conditions for the UNKNOWN benchmark.

P1 is a negative control for representation discovery. It tests whether an
agent can distinguish incorrect parameterization from representation-level
inadequacy.

No executable benchmark implementation is defined by this document.

---

## 1. Objective

The purpose of P1 is to construct environments in which:

1. the baseline representation R₀ is sufficient;
2. the selected model family M₀ is sufficient;
3. a valid true parameterization θ* exists inside M₀;
4. UNKNOWN initially operates with an intentionally incorrect θ₀;
5. θ* is identifiable under the permitted public experimental protocol;
6. parameter-only recovery is possible;
7. representation extension is unnecessary;
8. model-family expansion is unnecessary.

The scientific question is:

> Can UNKNOWN recognize that its current predictive failure is caused by
> incorrect parameter values and recover by revising parameters without
> inventing a new representation?

P1 is therefore a controlled negative case for representation discovery.

---

## 2. Relationship to D.5.3.1

D.5.3.1 established the distinction between:

- parameter failure;
- model-family failure;
- representation-level failure;
- non-identifiability.

D.5.3.2 instantiates the parameter-failure branch.

The boundary is:

```text
P1:
R₀ sufficient
M₀ sufficient
θ₀ incorrect
θ* exists
θ* identifiable
parameter-only recovery possible

versus:

M1:
R₀ sufficient
M₀ insufficient

and:

R1:
R₀ insufficient

and:

N1:
multiple materially different explanations remain
indistinguishable under the permitted protocol
```

---

## 3. Core Objects

Let:

```text
H      = public interaction history
R₀(H)  = baseline representation
M₀     = selected model family
𝓕(M₀)  = admissible mappings of M₀
θ      = model parameters
θ*     = true parameterization
θ₀     = initial UNKNOWN parameterization
Y      = environment outcome
```

The model prediction is:

```text
Ŷ = M₀(R₀(H); θ)
```

The true environment satisfies:

```text
Y = M₀(R₀(H); θ*)
```

The P1 initial condition satisfies:

```text
θ₀ ≠ θ*

while:

θ* ∈ Θ(M₀)

and:

M₀(R₀(H); θ*) = Y
```

for the relevant public history and evaluation protocol.

---

## 4. Parameter Definition

A parameter is a bounded, explicitly declared quantity inside a frozen
model family that changes the mapping from an already-valid representation
to outcomes without introducing new representational primitives.

**Parameters may include:**

- numerical coefficients
- thresholds
- rates
- gains
- bounded transition constants
- explicitly declared model-specific scalar or vector values

**Parameters do not include:**

- new entities
- new entity types
- new relations
- new relation arities
- new temporal operators
- new representation primitives
- new semantic categories
- new structural motifs
- evaluator metadata
- hidden-state variables promoted into the public representation

A stored parameter estimate remains a parameter estimate even if UNKNOWN
stores it explicitly or gives it a human-readable name.

Parameter storage is not representation extension.

---

## 5. Model-Family Requirement

P1 requires that the true mapping already belongs to the selected model
family.

Formally:

```text
θ* ∈ Θ(M₀)
```

and therefore:

```text
Recoverable(M₀, R₀, θ*) = TRUE
```

A condition must not be labeled P1 merely because a more expressive model
can fit the environment.

If no parameterization within M₀ can represent the correct mapping, the
condition is M1 rather than P1.

---

## 6. Baseline Representation Requirement

P1 requires:

```text
R₀ is sufficient
```

The required predictive information must already be present in R₀.

A P1 construction must not contain an R₀ representation collision of the
form:

```text
R₀(H₁) = R₀(H₂)

while:

Y(H₁) ≠ Y(H₂)
```

If such a collision is required to explain the failure, the condition is
representation-level inadequacy and therefore belongs to R1.

---

## 7. Canonical P1 World

The first canonical P1 construction uses a deterministic scalar controlled
dynamical system:

```text
s[t+1] = α * s[t] + β * u[t]
```

where:

- `s[t]` is the observable scalar state
- `u[t]` is the observable action/control
- `s[t+1]` is the observable resulting state
- `α` and `β` are hidden model parameters

The parameter vector is:

```text
θ = (α, β)
```

The true world uses:

```text
θ* = (α*, β*)
```

UNKNOWN initially uses:

```text
θ₀ = (α₀, β₀)

with:

θ₀ ≠ θ*
```

The canonical model family is:

```text
M₀(s[t], u[t]; α, β) = α * s[t] + β * u[t]
```

This construction is intentionally minimal.

Its purpose is to establish a mathematically auditable P1 control before
introducing relational, stochastic, or high-dimensional mechanisms.

---

## 8. Canonical Representation

The baseline representation contains:

```text
R₀ =
{
    current state,
    current action,
    resulting state,
    temporal position
}
```

The representation does not contain:

- α
- β
- P1
- condition_id
- failure_class
- evaluator diagnosis

The model parameters remain part of the model state rather than the
representation vocabulary.

---

## 9. Parameter Sufficiency

The canonical P1 construction must satisfy:

```text
∃ θ* such that:

M₀(R₀(H); θ*) = Y(H)
```

Therefore the representation and model family already contain the
information and functional capacity required for correct prediction.

Parameter revision is sufficient.

No representation extension is required.

---

## 10. Initial Parameter Failure

UNKNOWN begins with:

```text
θ₀ ≠ θ*
```

The initial parameterization must be deliberately incorrect but valid
within the declared parameter domain.

The benchmark should avoid trivial corruptions whose magnitude or form
directly reveals the condition class.

Examples of acceptable initial perturbations include:

- mild parameter displacement
- systematic parameter bias
- multi-parameter perturbation
- parameter hypotheses selected to create informative experimental
  uncertainty

The initial parameter state must not contain metadata identifying the
correct parameter.

---

## 11. Parameter Domain

The parameter domain must be declared before final evaluation.

Conceptually:

```text
Θ = Θ₁ × Θ₂ × ... × Θₙ
```

where every parameter has:

- declared type
- declared domain
- declared validity constraints
- declared sharing/dependency rules
- declared role in the model family

The domain cannot be adapted after observing UNKNOWN's evaluation behavior.

---

## 12. Identifiability

P1 requires parameter identifiability under the permitted public
experimental protocol.

Identifiability is not defined solely by the mathematical model.

It depends on:

- the model
- the baseline representation
- public observations
- available actions
- available interventions
- experiment protocol
- observation noise
- evaluation horizon

For the initial deterministic P1 control, the protocol should provide enough
independent observations to uniquely determine θ*.

---

## 13. Canonical Identifiability Witness

For:

```text
s[t+1] = α*s[t] + β*u[t]
```

two transitions provide:

```text
s[2] = α*s[1] + β*u[1]
s[3] = α*s[2] + β*u[2]
```

which can be written:

```text
[s[1]  u[1]] [α]   [s[2]]
[s[2]  u[2]] [β] = [s[3]]
```

The parameter vector is uniquely recoverable when the corresponding
observation matrix has sufficient rank.

For the two-parameter case:

```text
rank(X) = 2
```

is the required deterministic identifiability condition.

The evaluator must verify this independently.

UNKNOWN is not given the rank result.

---

## 14. P1 and N1 Boundary

If multiple materially different parameterizations produce identical
outcomes for every permitted experiment, the condition is not a clean P1.

It is N1.

For example, if all experiments satisfy:

```text
u[t] = 2*s[t]
```

then:

```text
s[t+1]
    = α*s[t] + β*(2*s[t])
    = (α + 2β)*s[t]
```

Only:

```text
α + 2β
```

is identifiable.

Individual values of α and β are not uniquely determined.

Therefore parameterizations such as:

```text
α = 0.8, β = 0.5
```

and:

```text
α = 1.2, β = 0.3
```

may remain observationally equivalent under that restricted protocol.

The resulting condition belongs to N1 unless additional permitted experiments
make the parameterization identifiable.

---

## 15. Structural Identifiability

Structural identifiability asks:

> Given the declared model and ideal observations under the permitted
> protocol, can the true parameterization be uniquely determined?

P1 requires structural identifiability in its canonical deterministic form.

This must be established before practical parameter-estimation performance
is evaluated.

---

## 16. Practical Identifiability

Practical identifiability additionally considers:

- finite observations
- finite interventions
- stochastic variation
- observation noise
- numerical precision
- parameter estimation error
- optimization behavior

These concerns are important but are deliberately separated from the first
canonical P1 control.

The first P1 layer should be deterministic and exact.

Later benchmark variants may introduce practical estimation difficulty.

---

## 17. Recovery Tolerance

The canonical P1 condition should avoid numerical tolerance as a definition
of ground-truth classification.

The evaluator knows:

```text
θ*
```

and can independently verify exact deterministic recovery.

Tolerance becomes relevant only when later variants introduce:

- continuous parameters
- noise
- approximate observations
- stochastic dynamics
- numerical estimation

Therefore:

```text
P1 classification ≠ optimizer convergence criterion
```

---

## 18. P1 and M1 Boundary

P1 requires:

```text
∃ θ* ∈ Θ(M₀)

such that:

M₀(R₀(H); θ*) = Y(H)
```

M1 instead requires:

```text
∀ θ ∈ Θ(M₀):
M₀(R₀(H); θ) ≠ Y(H)
```

for the relevant target mapping, while another model family can express the
mapping without changing R₀.

Therefore:

```text
P1: wrong parameter inside sufficient model family
M1: model family itself insufficient
```

---

## 19. P1 and R1 Boundary

P1 requires that R₀ preserve the distinctions needed by the target mapping.

If:

```text
R₀(H₁) = R₀(H₂)

but:

Y(H₁) ≠ Y(H₂)
```

then every deterministic model restricted to R₀ receives the same
representation for both histories.

No parameter change can distinguish them.

Therefore such a condition cannot be P1.

It is a candidate R1 construction.

---

## 20. P1 and X1 Boundary

The first P1 construction must use deterministic dynamics:

```text
ε[t] = 0
```

This ensures that observed prediction errors cannot be attributed to
stochastic environmental variation.

X1 is deferred until the stochastic control is independently validated.

Later mixed conditions may combine parameter error and stochastic variation,
but mixed conditions must not replace the clean P1 control.

---

## 21. P1 and Noise

A noisy extension may use:

```text
s[t+1] = α*s[t] + β*u[t] + ε[t]
```

but this is not part of canonical P1.

Noise can create uncertainty about whether an observed error originates from:

- incorrect parameters
- stochastic variation
- insufficient data
- model-family error
- representation inadequacy

Therefore noisy P1 conditions are a later robustness layer.

---

## 22. Matched Condition Principle

P1 must be constructed from the same underlying world-family machinery as
the other controlled failure conditions.

Conditions should share, where scientifically appropriate:

- observation schema
- entity structure
- action schema
- intervention schema
- parameter domain
- initial-state distributions
- timing
- identifiers
- episode structure
- noise configuration
- public interface

The scientifically relevant difference should be the controlled parameter
failure itself.

---

## 23. P1 Control Matrix

The initial benchmark taxonomy should include:

| Condition | R₀           | M₀           | Parameters       | Evidence     |
|-----------|--------------|--------------|------------------|--------------|
| R0        | sufficient   | sufficient   | correct          | sufficient   |
| P1        | sufficient   | sufficient   | initially wrong  | sufficient   |
| N1        | sufficient   | sufficient   | ambiguous        | insufficient |
| M1        | sufficient   | insufficient | correct          | sufficient   |
| R1        | insufficient | sufficient   | correct          | sufficient   |

This matrix is a conceptual control structure, not an aggregate score.

---

## 24. No Condition Metadata Leakage

UNKNOWN must not receive:

- condition_id
- failure_class
- representation_status
- model_family_status
- parameter_status
- identifiability_status
- θ*
- θ₀
- evaluator diagnosis

The public interface may expose:

- observations
- actions
- action outcomes
- intervention outcomes
- explicitly permitted public state
- timestamps/step information where defined by the public contract

---

## 25. Parameter Memorization Prohibition

UNKNOWN must not solve P1 by introducing a parameter per observation.

Invalid examples include:

```text
α₁
α₂
α₃
...
αₙ
```

when these merely memorize individual transitions.

The model family must define:

- parameter count
- parameter domains
- parameter sharing
- allowed dependencies
- parameter roles

A successful P1 solution must recover reusable parameter values rather than
memorize individual observations.

---

## 26. Parameter Estimation Method Neutrality

The benchmark does not prescribe an estimation algorithm.

UNKNOWN may use, where permitted:

- analytical estimation
- optimization
- Bayesian inference
- filtering
- online updating
- hypothesis search
- other valid parameter-revision strategies

The scientific target is parameter recovery, not a particular algorithm.

---

## 27. Passive P1

A passive P1 condition provides sufficient ordinary observations to identify
the parameters.

UNKNOWN does not need interventions.

This tests whether it can recognize and correct parameter error from ordinary
experience.

---

## 28. Active P1

An active P1 condition may require UNKNOWN to select informative actions or
interventions to efficiently distinguish parameter hypotheses.

The world remains P1 because parameter-only recovery remains sufficient.

The distinction is about experimental strategy, not ground-truth failure
class.

---

## 29. Intervention Role

Interventions are evidence, not parameter oracles.

The environment must return observable consequences of an intervention.

It must not return:

- parameter_correct
- parameter_wrong
- θ*
- diagnosis

UNKNOWN may use intervention outcomes to update parameter hypotheses.

---

## 30. Recovery Ladder

The canonical P1 evaluation should follow:

```text
Level 0
initial θ₀
    ↓
prediction failure

Level 1
parameter revision
    ↓
θ̂

Level 2
held-out prediction
    ↓
validation

Level 3
held-out intervention
    ↓
validation

Level 4
unseen initial state/context where applicable
    ↓
generalization
```

Expected P1 behavior:

- **Level 0:** failure
- **Level 1:** recovery
- **Level 2:** success
- **Level 3:** success
- **Level 4:** success where defined

Model-family expansion and representation extension should be unnecessary.

---

## 31. Over-Triggering Representation Discovery

P1 is also a negative control for UNKNOWN's representation-extension
behavior.

If UNKNOWN encounters P1 and unnecessarily creates a new representation,
the final predictive result alone must not erase this behavior.

The benchmark should separately record:

- parameter recovery
- representation expansion
- model-family expansion

This allows evaluation of whether UNKNOWN correctly identifies the level at
which its current abstraction is inadequate.

---

## 32. Held-Out Validation

Parameter recovery must not be evaluated solely on observations used to
identify θ.

Validation should include held-out:

- initial states
- actions
- transitions
- interventions
- contexts where applicable

A parameterization that fits observed transitions but fails on held-out
experiments is not sufficient evidence of successful recovery.

---

## 33. Reproducibility

Every P1 experiment must use the benchmark reproducibility contract.

Relevant identity fields include:

- experiment_id
- condition_id
- scenario_id
- trial_id
- seed
- configuration_id

The evaluator should retain the true:

- θ*
- θ₀

and all experiment configuration necessary for replay.

UNKNOWN should not receive hidden benchmark seed information unless that seed
is explicitly part of the public contract.

---

## 34. Ground-Truth Record

Conceptually, the evaluator-private P1 record contains:

- condition_id
- world_family
- seed
- representation_status
- model_family_status
- parameter_status
- θ*
- θ₀
- parameter_domain
- identifiability_status
- identifiability_witness
- public_protocol
- intervention_protocol
- noise_class
- recovery_witness

This record is evaluator-only.

---

## 35. P1 Acceptance Criteria

A canonical P1 condition must satisfy all of the following:

- **P1-A** — R₀ is sufficient.
- **P1-B** — M₀ contains the true mapping.
- **P1-C** — θ* exists inside M₀.
- **P1-D** — θ₀ is intentionally incorrect.
- **P1-E** — θ* is identifiable under the permitted protocol.
- **P1-F** — identifiability is evaluator-verified.
- **P1-G** — θ* and P1 metadata remain private.
- **P1-H** — public evidence contains sufficient information for recovery.
- **P1-I** — parameter-only recovery is possible.
- **P1-J** — representation extension is unnecessary.
- **P1-K** — model-family expansion is unnecessary.
- **P1-L** — canonical P1 is deterministic and noise-free.
- **P1-M** — held-out experiments validate recovery.
- **P1-N** — superficial statistics do not reveal P1.
- **P1-O** — parameter memorization is prohibited.
- **P1-P** — N1 is used when relevant parameterizations remain observationally indistinguishable.
- **P1-Q** — representation over-expansion is measured separately.
- **P1-R** — experiment configuration is reproducible.
- **P1-S** — the condition is generated from shared benchmark machinery.
- **P1-T** — the P1 classification is structurally established before UNKNOWN evaluation.

---

## 36. Deferred Variants

The following are explicitly deferred:

- **P1.1** — Continuous parameter recovery.
- **P1.2** — Bounded observation noise.
- **P1.3** — Stochastic dynamics.
- **P1.4** — Higher-dimensional parameter vectors.
- **P1.5** — Relational parameterized dynamics.
- **P1.6** — Mixed parameter + noise failure.
- **P1.7** — Mixed parameter + model-family failure.

Mixed conditions are deferred until clean controls are validated.

---

## 37. Anti-Circularity Rule

P1 must not be defined as:

> A condition where parameter updating improves UNKNOWN's score.

Instead, P1 is defined structurally by:

- representation sufficiency
- model-family sufficiency
- existence of θ*
- incorrect θ₀
- identifiability
- parameter-only recoverability

Improved performance is evidence supporting recovery, not the definition of
P1.

---

## 38. Scientific Interpretation

A successful P1 result means:

> UNKNOWN encountered predictive failure even though its representation and
> model family were adequate, inferred that parameter values were inadequate,
> and recovered a reusable parameterization through permitted evidence.

It does not demonstrate:

- concept discovery
- representation discovery
- causal discovery
- general intelligence
- autonomous scientific reasoning

The claim is deliberately narrower.

---

## 39. Research Decision

The canonical P1 construction is accepted as a valid controlled failure
class.

The strongest construction is the deterministic scalar system:

```text
s[t+1] = α*s[t] + β*u[t]
```

because:

- the representation is explicit
- the model family is explicit
- the parameter vector is explicit
- identifiability can be mathematically verified
- P1 and N1 can be constructed with the same model family
- P1 and M1 can be separated
- P1 and R1 can be separated
- noise can be excluded initially
- parameter recovery can be independently validated

This construction should become the canonical unit test for the benchmark's
P1 semantics before more complex world families are introduced.
