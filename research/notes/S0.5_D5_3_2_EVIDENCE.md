# S0.5-D.5.3.2 — P1 Parameter-Failure Construction Evidence

## 1. Objective

Define a scientifically controlled P1 condition in which:

- the baseline representation is sufficient;
- the selected model family is sufficient;
- the initial parameterization is deliberately incorrect;
- the correct parameterization exists;
- the correct parameterization is identifiable;
- parameter-only recovery is possible;
- representation extension is unnecessary.

---

## 2. Research Question

The central question is:

> Can UNKNOWN distinguish incorrect parameterization from representation-level
> inadequacy and recover by revising parameters without inventing a new
> representation?

---

## 3. Starting Boundary

D.5.3.1 established:

```text
P1 → parameter problem
M1 → model-family problem
R1 → representation problem
N1 → insufficient/non-identifiable evidence
```

D.5.3.2 specializes the P1 branch.

---

## 4. Core Decision

A P1 condition requires:

```text
R₀ sufficient
M₀ sufficient
θ₀ incorrect
θ* exists
θ* identifiable
parameter-only recovery possible
```

This definition is structural.

It is not based on UNKNOWN's eventual score.

---

## 5. Parameter Semantics Decision

A parameter is defined as a bounded quantity inside a frozen model family
that changes the mapping from an already-valid representation to outcomes.

Parameters do not introduce:

- new representation primitives
- new relations
- new structural motifs
- new temporal operators
- hidden variables
- evaluator information

Therefore:

```text
parameter estimate ≠ representation extension
```

This prevents ordinary model fitting from being mislabeled as concept
formation.

---

## 6. Canonical World Decision

The first P1 construction uses:

```text
s[t+1] = α*s[t] + β*u[t]
```

with:

```text
θ = (α, β)
```

The baseline representation contains:

```text
s[t]
u[t]
s[t+1]
time
```

The model family is:

```text
M₀(s[t], u[t]; α, β) = α*s[t] + β*u[t]
```

This is intentionally minimal and analytically verifiable.

---

## 7. Why This Construction Is Suitable

The canonical construction provides explicit separation between:

- representation
- model family
- parameters
- observations
- interventions

It also allows the evaluator to prove identifiability rather than infer it
from optimizer behavior.

This makes it suitable as the first P1 scientific control.

---

## 8. Initial Parameter Failure

The true parameterization is:

```text
θ*
```

UNKNOWN initially operates with:

```text
θ₀
```

such that:

```text
θ₀ ≠ θ*
```

The incorrect parameterization must remain inside the declared valid
parameter domain.

The difference must not be exposed through metadata.

---

## 9. Model-Family Sufficiency

The evaluator must establish:

```text
θ* ∈ Θ(M₀)
```

Therefore the true mapping already belongs to the selected model family.

If no parameter vector inside M₀ can recover the true mapping, the condition
is M1, not P1.

---

## 10. Representation Sufficiency

The evaluator must establish that the required predictive information is
already represented by R₀.

The construction must not depend on:

```text
R₀(H₁) = R₀(H₂)

while:

Y(H₁) ≠ Y(H₂)
```

Such a collision belongs to R1.

---

## 11. Identifiability Decision

P1 requires identifiability under the permitted public experimental
protocol.

For the canonical two-parameter system, observations form:

```text
[s[1]  u[1]]
[s[2]  u[2]]
```

and the parameter vector is identifiable when:

```text
rank(X) = 2
```

The evaluator independently verifies this.

UNKNOWN does not receive the identifiability result.

---

## 12. P1/N1 Boundary

A non-identifiable construction is not P1.

Example:

```text
u[t] = 2*s[t]
```

causes:

```text
s[t+1]
= α*s[t] + β*(2*s[t])
= (α+2β)*s[t]
```

Only the combined quantity:

```text
α + 2β
```

is identifiable.

Different parameterizations can therefore remain observationally equivalent.

Such a condition is N1 unless the permitted experiment protocol is expanded
in a way that makes the parameters distinguishable.

---

## 13. Why N1 Is Necessary

Without the N1 boundary, UNKNOWN could be penalized for failing to recover a
parameter that the public evidence cannot uniquely determine.

That would turn benchmark ambiguity into apparent agent failure.

Therefore:

> If materially different explanations remain compatible with every
> permitted experiment, the benchmark must classify the condition as N1.

---

## 14. P1/M1 Boundary

P1:

```text
∃ θ* ∈ Θ(M₀)
```

M1:

```text
∀ θ ∈ Θ(M₀), correct mapping unavailable
```

while another model family can recover the mapping without changing R₀.

Therefore model-family sufficiency must be established independently of
UNKNOWN's recovery behavior.

---

## 15. P1/R1 Boundary

P1 requires that R₀ preserve all distinctions required by the target
mapping.

If:

```text
R₀(H₁) = R₀(H₂)

but:

Y(H₁) ≠ Y(H₂)
```

then no parameter setting inside a deterministic model operating only on R₀
can distinguish the cases.

This is representation-level inadequacy.

Therefore:

```text
P1 ≠ R1
```

---

## 16. P1/X1 Boundary

Canonical P1 uses deterministic dynamics:

```text
ε[t] = 0
```

This isolates parameter failure from stochastic variation.

Noise is deliberately deferred.

The first stochastic benchmark must independently establish X1 before mixed
P1/X1 conditions are introduced.

---

## 17. Recovery Decision

Parameter recovery is evaluated using:

- fitting/recovery evidence
- held-out transitions
- held-out initial states
- held-out actions
- held-out interventions where applicable

Success on the fitting observations alone is insufficient.

---

## 18. Intervention Decision

Interventions may be used to distinguish competing parameter hypotheses.

They provide observable evidence.

They do not provide:

- θ*
- P1 label
- diagnosis

The environment remains an experimental object rather than a parameter oracle.

---

## 19. Passive and Active P1

Two evaluation modes are allowed.

**Passive P1**

Ordinary observations contain enough information for recovery.

**Active P1**

UNKNOWN may need to select informative actions/interventions.

Both remain P1 because the underlying failure is still parameterization.

The distinction concerns experimental strategy, not ground truth.

---

## 20. Parameter Estimation Method Neutrality

The benchmark does not prescribe an estimation algorithm.

Valid approaches may include:

- analytical estimation
- optimization
- Bayesian inference
- filtering
- online updating
- hypothesis search

The benchmark evaluates the scientific result, not the implementation
method.

---

## 21. Matched Controls

P1 must be generated using the same world-family machinery as other
benchmark conditions.

Where scientifically appropriate, matched conditions share:

- observation schema
- action schema
- intervention schema
- entity structure
- initial-state distribution
- timing
- parameter domain
- noise configuration
- identifiers
- episode structure

The failure class must not be revealed through superficial statistics.

---

## 22. Negative-Control Role

P1 is a negative control for representation discovery.

A capable system should not respond to every predictive failure by creating a
new representation.

For P1:

```text
parameter revision
```

should be sufficient.

If UNKNOWN creates an unnecessary representation extension, that behavior
must be recorded independently of final predictive performance.

---

## 23. Parameter Memorization Control

UNKNOWN cannot introduce one parameter per observed transition.

The model family must freeze:

- parameter vocabulary
- parameter count
- parameter domains
- parameter sharing
- dependency structure

Otherwise arbitrary memorization could masquerade as parameter recovery.

---

## 24. Noise Control

Canonical P1:

```text
deterministic
```

Later variants:

```text
P1 + observation noise
P1 + stochastic dynamics
P1 + mixed failures
```

are deferred.

This prevents the first P1 benchmark from confounding parameter error with
stochastic variation.

---

## 25. Reproducibility

P1 follows the benchmark seed and experiment identity contract.

The evaluator records:

- experiment_id
- condition_id
- scenario_id
- trial_id
- seed
- configuration_id
- θ*
- θ₀

UNKNOWN does not receive hidden evaluator metadata.

---

## 26. Ground-Truth Privacy

Evaluator-private information includes:

- θ*
- θ₀
- P1 label
- identifiability status
- model-family status
- representation status
- recovery witness

Public information includes only what the environment contract permits.

This maintains the established public/private boundary.

---

## 27. Acceptance Criteria

P1 is acceptable only if:

- R₀ sufficient
- M₀ sufficient
- θ* exists
- θ₀ incorrect
- θ* identifiable
- parameter-only recovery possible
- representation extension unnecessary
- model-family expansion unnecessary
- canonical condition deterministic
- held-out validation possible
- superficial leakage controlled
- parameter memorization prevented
- evaluator truth private

---

## 28. Scientific Risks

Remaining risks are:

- accidentally defining P1 through performance
- allowing parameter vocabulary to expand dynamically
- confusing parameter estimates with representation extensions
- allowing hidden information into the model
- constructing a condition that is actually M1
- constructing a condition that contains an R₀ collision
- constructing a condition that is actually N1
- introducing noise before X1 is independently controlled
- allowing superficial statistics to reveal P1
- validating only on fitting data

These risks are addressed by the structural acceptance criteria.

---

## 29. Scientific Review

The P1 construction was reviewed against the established D.5.3.1
boundaries.

**PASS**

- parameter semantics
- model-family sufficiency
- representation sufficiency
- P1/N1 separation
- P1/M1 separation
- P1/R1 separation
- P1/X1 separation
- evaluator privacy
- identifiability verification
- held-out validation
- intervention neutrality
- parameter memorization controls
- matched-condition controls

**DEFERRED**

- continuous parameters
- stochastic dynamics
- noisy observations
- mixed P1/X1 conditions
- high-dimensional parameter spaces
- relational parameterized dynamics

These are robustness layers, not blockers for the canonical P1 control.

---

## 30. Research Decision

The canonical P1 construction is accepted.

The deterministic scalar controlled system:

```text
s[t+1] = α*s[t] + β*u[t]
```

provides a clean first benchmark because:

- R₀ is explicit
- M₀ is explicit
- θ is explicit
- θ* is evaluator-verifiable
- θ₀ can be deliberately incorrect
- identifiability can be checked mathematically
- N1 can be constructed by restricting experimental variation
- M1 can be separated by changing model-family capability
- R1 can be separated through representation collisions
- X1 can be excluded initially

The canonical construction is therefore suitable as the first executable P1
unit once the broader D.5 benchmark implementation begins.
