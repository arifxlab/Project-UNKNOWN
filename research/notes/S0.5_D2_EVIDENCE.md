---

## 2. Objective

S0.5-D.2 hardens the deterministic world transition system established during S0.5-B.

The objective is not to introduce new scientific mechanisms. The objective is to verify that the existing transition system can serve as reliable experimental infrastructure.

The target transition is:

$$
S_{t+1}=T(S_t,A_t)
$$

For a fixed initial configuration, seed, and action sequence, the resulting trajectory must be reproducible.

The transition system must also preserve its declared state invariants and reject invalid inputs without partially mutating the world.

---

## 3. Scientific Role

The deterministic world is experimental infrastructure for later stages.

Future stages will require controlled comparisons among:

* parameter failure,
* model-family failure,
* representation failure,
* information-unavailable conditions,
* unnecessary or decoy candidate explanations.

Those comparisons are only meaningful if the underlying world transition itself is deterministic and stable.

D.2 therefore establishes a trustworthy baseline before introducing interventions and benchmark conditions.

## 5. Authoritative Transition Boundary

The deterministic world remains the single authoritative transition system.

Actions are applied through:

$$
S_{t+1}=T(S_t,A_t)
$$

The public runtime does not independently simulate world dynamics.

This preserves a single source of truth for future experimental conditions.

---

## 6. Transition Validation Order

The hardened transition path follows the principle:

```text
validate input
    ↓
compute next state
    ↓
commit state
    ↓
evaluate terminal status
```

Validation occurs before state mutation.

Therefore, an invalid action must raise an error without partially changing the current world state.

This property is explicitly tested.

---

## 7. Numeric Input Hardening

MOVE actions now reject non-finite vector components.

The transition system rejects:

* `NaN`;
* positive infinity;
* negative infinity.

This prevents invalid floating-point values from entering the state trajectory and contaminating subsequent observations.

Configuration validation also explicitly distinguishes integer values from booleans.

In particular, Python's `bool` subtype relationship with `int` is not treated as sufficient evidence that a boolean is a valid numeric configuration value.

The following are rejected:

* boolean `max_steps`;
* boolean `entity_count`.

---

## 8. Deterministic Trajectory Verification

A dedicated trajectory test executes a multi-step action sequence and verifies that two independently initialized worlds produce identical trajectories.

The comparison covers the resulting world states across the sequence.

The required reproducibility condition is:

$$
(W_0,\ A_0,\ A_1,\ldots,A_n,\ seed)
\Rightarrow
(W_1,\ldots,W_n)
$$

and repeated execution with the same inputs must produce the same sequence.

No additional runtime randomness is introduced by the transition layer.

---

## 9. Transition Atomicity

An invalid action must not mutate the world.

The test protocol is:

1. initialize the world;
2. capture the current state;
3. submit an invalid action;
4. assert that the expected validation error is raised;
5. capture the state again;
6. compare the before and after states.

The state must remain unchanged.

This is important because partial mutation would invalidate later experimental comparisons even if the transition eventually raises an exception.

---

## 10. State Invariants

D.2 verifies the following invariants during ordinary transitions.

### Entity identity

Entity identifiers remain stable across ordinary action transitions.

### Mass

Entity mass remains unchanged by ordinary actions.

### Position bounds

Entity positions remain inside the configured world boundaries.

### Relations

The static relation structure remains stable during ordinary actions.

### State immutability

`WorldState` and `EntityState` are immutable data structures.

The entity and relation collections are also stored in immutable tuple form.

These constraints reduce accidental mutation of experimental state.

---

## 11. Action Semantics Verified

The existing action semantics remain unchanged.

### NO_OP

NO_OP does not modify entity velocity.

### MOVE

MOVE changes the target entity's velocity according to the supplied vector and then advances the world using the configured timestep.

The baseline kinematic transition remains:

$$
p_{t+1}=p_t+v_t\Delta t
$$

### INTERACT

INTERACT remains structurally validated but does not introduce additional transition physics at this stage.

D.2 deliberately does not expand the physical model.

---

## 12. Terminal and Reset Semantics

The world continues to use deterministic step-based termination.

Once the configured horizon is reached, additional ordinary stepping is rejected according to the existing terminal-state contract.

Resetting the world after termination creates a fresh deterministic trajectory from the supplied configuration and seed.

This behavior is explicitly tested.

---

## 13. Scientific Boundary Preservation

D.2 does not introduce hidden scientific information into the public transition path.

The following remain outside the current transition implementation:

* ground-truth benchmark labels;
* hidden condition labels;
* evaluation outcomes;
* representation-quality scores;
* candidate concepts;
* oracle predictions;
* discovery decisions.

The world remains an environment rather than a discovery system.

## 17. Scientific Interpretation

The result of D.2 is infrastructure-level evidence.

The environment now has explicit protection against several classes of accidental experimental corruption:

* invalid numeric state contamination;
* partial mutation after failed actions;
* nondeterministic multi-step trajectories;
* identity drift;
* mass drift;
* boundary violations;
* accidental mutable state;
* relation drift during ordinary actions.

These protections are prerequisites for later controlled experiments.

---

## 18. Limitations

The current world remains intentionally simple.

It does not yet model:

* authoritative interventions;
* hidden dynamic variables;
* controlled causal mechanisms;
* paired counterfactual benchmark conditions;
* model-family controls;
* parameter controls;
* decoy explanations;
* unseen-context transfer.

Those mechanisms belong to subsequent D stages and must be introduced deliberately rather than implicitly through hardening work.
