# S0.5-D.5.3 Evidence

## D.5.3.1 Model-Family Semantics & Recovery Capability Boundary

### Status

**CLOSED** — research/design contract established.

---

## 1. Research Objective

Determine how the executable benchmark will distinguish:

- parameter failure;
- model-family failure;
- representation-level inadequacy;
- representation extension.

The principal threat is allowing model-family expansion to silently alter the representation boundary.

---

## 2. Decision

The benchmark separates three levels:

```
Representation
      ↓
Model family
      ↓
Parameters
```

- A **model-family change** may alter only the mapping class.
- A **parameter change** may alter only parameter values.
- A **representation extension** changes the admissible representation closure.

---

## 3. Model-Family Contract

A model family is defined as a class of admissible mappings from a fixed representation to benchmark outcomes.

Conceptually:

```
F(M) = admissible mapping class

with:

M₀ : Closure(R₀) → Y
M₁ : Closure(R₀) → Y
```

where `M₁` may have a richer mapping class than `M₀`.

The representation remains fixed.

---

## 4. Model-Family Invariant

A valid model-family comparison may **not**:

- access raw observations outside `R₀`;
- access hidden state;
- access evaluator truth;
- introduce new primitives;
- introduce new relations;
- dynamically expand the representation language;
- bypass the representation interface.

If it does, the comparison is not a pure model-family experiment.

---

## 5. Baseline Closure Contract

The baseline representation is:

```
R₀ = (V₀, T₀, O₀, C₀)
```

Closure is:

```
Closure(R₀)
=
all finite, well-typed structures derivable
from V₀ using O₀ under C₀
and the declared semantic-equivalence rules.
```

The closure is determined before UNKNOWN's final evaluation.

---

## 6. Why Explicit Closure Is Required

Without an explicit closure definition, the benchmark could incorrectly classify:

- difficult computation;
- optimization failure;
- model-family failure;
- search failure;

as representation discovery.

Closure provides the reference boundary against which such claims can be tested.

---

## 7. Rejected Closure Policies

### 7.1 Arbitrary Depth-Only Boundary

Rejected:

```
R₀ = expressions of depth <= N
R₁ = expressions of depth N+1
```

unless an independent scientific reason exists for that boundary.

Composition depth alone does not establish representational novelty.

### 7.2 Performance-Defined Closure

Rejected:

```
UNKNOWN cannot solve X
therefore X is outside R₀
```

This is circular.

### 7.3 Unrestricted Universal Function

Rejected:

```
R₀ includes arbitrary function(raw_observation)
```

This collapses representation into unrestricted computation.

---

## 8. Expressibility vs Discoverability

The benchmark must distinguish:

```
Expressible(R₀, c)
```

from:

```
Discoverable(UNKNOWN, c)
```

A structure may be expressible but not discovered.

That is not R1 evidence.

This distinction protects the benchmark from turning search difficulty into representation inadequacy.

---

## 9. Semantic Equivalence

Syntactic difference is not sufficient for representation novelty.

Two different expressions may represent the same structure.

Therefore the executable benchmark must eventually define semantic-equivalence rules appropriate to the finite typed representation language.

Potential mechanisms include:

- canonicalization;
- symbolic normalization;
- finite-domain equivalence;
- typed structural equivalence;
- semantic witnesses.

Unresolved equivalence must not automatically be treated as novelty.

---

## 10. Internal Computation

A model may compute arbitrary intermediate quantities permitted by its model-family contract.

Such internal quantities do not automatically constitute representation extensions.

- If a computed quantity belongs to `Closure(R₀)`, it remains baseline computation.
- If it does not belong to `Closure(R₀)`, then the model has crossed the representation boundary and the experiment must be treated as an extension or contract violation.

---

## 11. R1 Constructive Witness

The central R1 construction is an `R₀` collision.

Find:

```
H₁, H₂
```

such that:

```
R₀(H₁) = R₀(H₂)

but:

Y(H₁) ≠ Y(H₂)
```

No deterministic downstream mapping operating solely on `R₀` can distinguish the two histories.

A valid extension must produce:

```
R₁(H₁) ≠ R₁(H₂)
```

This provides a constructive representation-level witness.

---

## 12. Failure Taxonomy

| Condition | Representation | Model Family | Parameters |
|---|---|---|---|
| R0 | sufficient | sufficient | correct/learnable |
| P1 | sufficient | sufficient | incorrect |
| M1 | sufficient | insufficient | irrelevant |
| R1 | insufficient | insufficient over R₀ | irrelevant |
| R1 + extension | extended | sufficient | learnable |

---

## 13. P1 Boundary

P1 requires:

```
Recoverable(M₀, R₀, f*) = true
```

but current parameters are incorrect.

A valid parameter update can recover the target without changing:

- `R₀`;
- model family;
- representation closure.

---

## 14. M1 Boundary

M1 requires:

```
Recoverable(M₀, R₀, f*) = false
Recoverable(M₁, R₀, f*) = true
```

while `R₀` remains sufficient.

Therefore M1 demonstrates mapping-class insufficiency rather than representation insufficiency.

---

## 15. R1 Boundary

R1 requires:

```
R₀(H₁) = R₀(H₂)
Y(H₁) ≠ Y(H₂)
```

and a valid extension:

```
R₁(H₁) ≠ R₁(H₂)
```

with the relevant distinction publicly recoverable.

This prevents a richer model family from being incorrectly credited with solving a representation problem.

---

## 16. Anti-Circularity Controls

The benchmark must prevent:

- changing `R₀` after seeing UNKNOWN failures;
- defining candidates based on performance;
- defining representation novelty by benchmark improvement;
- allowing evaluator truth into model-family experiments;
- treating internal model features as automatic concepts;
- treating expression depth alone as semantic novelty.

---

## 17. Freeze Requirement

Before final UNKNOWN evaluation, freeze:

- `V₀`
- `T₀`
- `O₀`
- `C₀`
- semantic-equivalence policy
- serialization/canonicalization policy

The final evaluation must not alter these definitions.

---

## 18. Evidence Ordering

The intended order is:

```
Structural definition
        ↓
Public recoverability
        ↓
R₀ collision
        ↓
Parameter recovery attempt
        ↓
Model-family recovery attempt
        ↓
Extension
        ↓
Prediction
        ↓
Intervention
        ↓
Falsification
        ↓
Transfer
```

The ordering prevents performance from becoming the definition of representation failure.

---

## 19. Scientific Risks Remaining

The following remain open for executable benchmark design:

**RISK-1 — Semantic equivalence**
How can equivalence be tested safely and reproducibly?

**RISK-2 — Primitive scope**
Which primitives belong in `V₀` independently of the target conditions?

**RISK-3 — Operator scope**
Which operators belong in `O₀` without making closure trivial or artificially weak?

**RISK-4 — Composition semantics**
How should `C₀` constrain valid compositions?

**RISK-5 — Collision construction**
How should R1 collision witnesses be generated automatically?

**RISK-6 — Model-family contracts**
How should `M₀` and `M₁` be specified so that their information boundaries remain auditable?

**RISK-7 — Extension validity**
How should candidate extensions be serialized, executed, compared, and validated?

These are implementation/design questions, not reasons to weaken the D.5.3.1 conceptual contract.

---

## 20. Scientific Review

**PASS**

- model-family semantics;
- representation/model separation;
- parameter/model separation;
- frozen `R₀` closure;
- explicit grammar requirement;
- prohibition of unrestricted computation;
- expressibility/discoverability separation;
- semantic-equivalence requirement;
- constructive R1 collision;
- anti-circularity;
- model-family isolation.

**DEFERRED**

- exact representation grammar;
- exact primitive vocabulary;
- exact semantic-equivalence implementation;
- executable collision generator;
- executable model-family interfaces;
- candidate extension runtime;
- complexity accounting.

---

## 21. Final Research Decision

D.5.3.1 is conceptually closed.

The benchmark will treat:

- **P1** as parameter insufficiency,
- **M1** as mapping-class insufficiency over a fixed representation,

and:

- **R1** as a representation-equivalence collision that cannot be resolved by any admissible mapping over the frozen baseline representation.

Representation extension must therefore change the admissible representation closure rather than merely introduce another internal model computation.
