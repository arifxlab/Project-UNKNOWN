# 1. Purpose

The benchmark must distinguish failures caused by:

- incorrect parameters;
- insufficient model-family expressiveness;
- insufficient baseline representation;
- insufficient evidence or non-identifiability;
- stochastic variation.

The central risk is misclassifying a model-family limitation as representation-level inadequacy, or vice versa.

D.5.3.1 therefore establishes a frozen semantics for model families and the baseline representation closure.

The central distinction is:

> Model-family expansion changes the admissible mapping class over a fixed representation. Representation extension changes the admissible representation closure itself.

---

# 2. Core Objects

Let:

- `H` = public interaction history;
- `P(H)` = public information available to UNKNOWN;
- `R₀(H)` = baseline representation of that public history;
- `Closure(R₀)` = all valid representational structures derivable under the frozen R₀ language;
- `M` = a model family;
- `θ` = model parameters;
- `Y` = benchmark outcome;
- `f*` = target mapping required by the world.

Prediction is conceptually:

    Ŷ = M(R₀(H); θ)

The representation and model-family boundaries must remain separate.

---

# 3. Model-Family Definition

A model family is not defined by:

- a neural-network architecture name;
- parameter count;
- implementation language;
- model size;
- observed benchmark performance;
- optimization algorithm.

Instead:

> A model family is a formally declared class of admissible mappings from a fixed representation language to benchmark outcomes.

For a model family `M`:

    F(M) = admissible mapping class

A model-family expansion is represented conceptually as:

    F(M₀) ⊂ F(M₁)

while the input representation remains fixed:

    Closure(R₀)

Thus:

    M₀ : Closure(R₀) → Y
    M₁ : Closure(R₀) → Y

may differ in mapping capability without changing the representation vocabulary.

---

# 4. Model-Family Invariant

The fundamental invariant is:

> Model-family expansion may enlarge the mapping class but may not introduce new representational information.

A valid model-family experiment therefore cannot:

- access raw observations that R₀ excludes;
- access hidden environment state;
- access evaluator-private truth;
- introduce a new primitive;
- introduce a new relation type;
- introduce a new representational operator;
- dynamically expand the representation grammar;
- bypass the public representation boundary.

If a model-family experiment does any of these things, it is no longer a pure model-family experiment.

---

# 5. Representation Closure

The baseline representation is defined as:

    R₀ = (V₀, T₀, O₀, C₀)

where:

- `V₀` = primitive vocabulary;
- `T₀` = type system;
- `O₀` = permitted representation operators;
- `C₀` = composition constraints.

The closure is:

> The set of all finite, well-typed representational structures derivable from V₀ using O₀ under C₀ and the declared semantic-equivalence rules.

Conceptually:

    Closure(R₀)
      = Derive(V₀, T₀, O₀, C₀)

Closure is determined by the representation contract.

It is not inferred from UNKNOWN's behavior.

---

# 6. R₀ Closure Must Be Frozen Before UNKNOWN Evaluation

The following must be specified before final evaluation:

- primitive vocabulary;
- primitive types;
- operator vocabulary;
- operator signatures;
- composition rules;
- representational constraints;
- allowed temporal scope;
- semantic-equivalence policy;
- serialization/canonicalization policy;
- prohibited unrestricted operations.

UNKNOWN's performance must not influence these decisions.

In particular:

    UNKNOWN fails to discover X

does not imply:

    X ∉ Closure(R₀)

Similarly:

    UNKNOWN discovers X

does not imply:

    X ∈ Closure(R₀)

Expressibility and discoverability are separate scientific properties.

---

# 7. Explicit Grammar Requirement

R₀ must be a finite, explicitly declared representation language.

A conceptual grammar may contain forms such as:

    Expression ::=
        Primitive
      | UnaryOperator(Expression)
      | BinaryOperator(Expression, Expression)
      | RelationOperator(Expression, Expression)
      | AggregateOperator(Expression, Set)
      | TemporalOperator(Expression, History)

The actual grammar will be defined later in the executable benchmark specification.

The important requirement is that every valid representation has an explicit derivation under the frozen grammar.

---

# 8. No Unrestricted Computation

R₀ must not contain an unrestricted function constructor such as:

    ArbitraryFunction(public_observation)

or:

    UniversalProgram(public_observation)

Such an operator would collapse the distinction between:

- representation;
- computation;
- arbitrary program synthesis.

If arbitrary computation over raw observations were admitted into R₀, Closure(R₀) could become effectively universal and meaningful representation-level failure would become difficult or impossible to define.

Therefore R₀ explicitly excludes unrestricted computation over raw observations.

---

# 9. Finite Representational Terms

Valid R₀ representations are finite constructions.

Infinite recursive definitions are not automatically members of Closure(R₀).

This requirement prevents the representation language from acquiring unrestricted computational power through implicit recursion.

The executable specification must define any finite resource limits necessary for safe evaluation separately from the scientific definition of expressibility.

---

# 10. Composition Depth Is Not Sufficient Evidence of Novelty

An arbitrary depth limit must not be used as the primary definition of representation novelty.

For example:

    R₀ depth ≤ 3
    R₁ depth = 4

does not by itself establish representation-level inadequacy.

If the depth-four structure is semantically expressible using the baseline language, then it remains an R₀-expressible structure.

Therefore:

> Computational difficulty, expression length, or composition depth alone does not establish R1.

Composition constraints remain part of C₀, but they must be independently justified before benchmark evaluation.

---

# 11. Expressibility vs Discoverability

Two distinct questions must be evaluated.

### Expressibility

Can the required structure be represented under the frozen baseline language?

    Expressible(R₀, c)

### Discoverability

Can UNKNOWN discover or construct the structure?

    Discoverable(UNKNOWN, c)

These must never be conflated.

Possible outcomes include:

    Expressible = true
    Discoverable = false

This is not evidence of R1.

It may instead indicate:

- search failure;
- learning failure;
- parameter failure;
- optimization failure;
- exploration failure;
- insufficient model-family capability.

---

# 12. Semantic Equivalence

Syntactic novelty is insufficient.

For example:

    distance(x, y)

and:

    sqrt((x₁ - y₁)² + (x₂ - y₂)²)

may be syntactically different but semantically equivalent under a declared world semantics.

Therefore candidate novelty must be evaluated against semantic equivalence, not merely expression-string equality.

The benchmark must eventually define a representation-equivalence procedure appropriate to its finite typed language.

Potential implementation mechanisms may include:

- canonicalization;
- symbolic normalization;
- finite-domain exhaustive equivalence;
- typed structural equivalence;
- benchmark-specific semantic witnesses.

The exact mechanism is deferred to executable benchmark specification.

---

# 13. No Universal Semantic-Equivalence Assumption

The benchmark does not assume that arbitrary semantic equivalence over unrestricted programs is computationally decidable.

Instead, equivalence will be defined relative to the frozen benchmark representation language and its declared semantics.

The executable benchmark must specify:

1. what constitutes semantic equality;
2. what domains are considered;
3. whether equivalence is exact or bounded;
4. what constitutes an unresolved equivalence case.

An unresolved equivalence case must not automatically be labeled as representation novelty.

---

# 14. Internal Model Computation Is Not Automatically Representation Extension

A model may calculate intermediate quantities internally.

For example:

    z = f(R₀)

does not automatically imply:

    R₁ = R₀ ∪ {z}

If `z` is expressible within Closure(R₀), it is ordinary model computation.

A persistent internal feature is not automatically a new concept.

Therefore:

> Representation extension requires a change to the admissible representation language, not merely the existence of an intermediate neural or computational quantity.

---

# 15. Representation Extension

A representation extension is conceptually:

    R₁ = Extend(R₀, c)

where `c` is a representational construct.

A valid candidate extension must satisfy, at minimum:

1. structural specification;
2. public provenance;
3. non-equivalence to existing R₀ structures;
4. explicit reusable semantics;
5. scientifically relevant consequences;
6. falsifiable predictions;
7. eventual transfer evaluation where applicable.

A candidate must not be accepted merely because it improves a benchmark score.

---

# 16. Model-Family Failure

M1 is defined by representation sufficiency combined with model-family insufficiency.

Conceptually:

    Recoverable(M₀, R₀, f*) = false

while:

    Recoverable(M₁, R₀, f*) = true

and:

    R₀ is sufficient

Thus the richer model family solves the task without changing the representation.

The critical invariant is:

    Representation(M₀) = Representation(M₁) = R₀

Only the mapping class changes.

---

# 17. Parameter Failure

P1 is distinct from M1.

For P1:

    Recoverable(M₀, R₀, f*) = true

but the current parameterization is incorrect:

    θ_current ≠ θ*

and some valid parameter setting exists:

    θ* ∈ Θ(M₀)

Therefore parameter optimization can recover the required mapping without:

- changing R₀;
- changing the model family;
- introducing a representation extension.

---

# 18. Representation-Level Failure

R1 requires representation-level inadequacy.

The core constructive witness is an R₀ representation collision.

Find public histories H₁ and H₂ such that:

    R₀(H₁) = R₀(H₂)

while:

    Y(H₁) ≠ Y(H₂)

Then any deterministic downstream model whose input is restricted to R₀ receives the same representation for both histories.

Therefore no mapping over R₀ can distinguish the required outcomes.

This is a constructive witness of representation inadequacy.

---

# 19. Why the Collision Witness Matters

The benchmark does not need to prove that every conceivable computational mechanism in the universe cannot solve the problem.

Instead it establishes:

1. the public histories are distinct;
2. the baseline representation maps them to the same representation;
3. the required outcome differs;
4. the model-family receives only the baseline representation.

Therefore:

    same R₀ input
          +
    different required output
          =
    no deterministic mapping over R₀ can solve both

This provides a concrete scientific boundary.

---

# 20. Extension Recovery

For a valid R1 construction, a candidate extension R₁ must separate the collision:

    R₁(H₁) ≠ R₁(H₂)

while preserving the relevant public information boundary.

The benchmark then tests whether a suitable model family can exploit that distinction.

Conceptually:

    R₀(H₁) = R₀(H₂)
    R₁(H₁) ≠ R₁(H₂)

and:

    Y(H₁) ≠ Y(H₂)

This establishes the structural role of the extension.

It does not by itself establish that the extension is a reusable scientific abstraction.

That requires further evidence.

---

# 21. Model-Family vs Representation Boundary

The controlled taxonomy is:

| Condition | Representation | Mapping Class | Parameters |
|---|---|---|---|
| R0 | sufficient | sufficient | correct/learnable |
| P1 | sufficient | sufficient | incorrect |
| M1 | sufficient | insufficient | irrelevant |
| R1 | insufficient | insufficient over R₀ | irrelevant |
| R1 + extension | extended | sufficient | learnable |

The distinction is causal:

### P1

Change parameters.

### M1

Change mapping class.

### R1

Change representation.

---

# 22. Invalid M1 Recovery

An M1 recovery experiment is invalid if the supposedly richer model:

- reads raw observations unavailable to R₀;
- accesses hidden variables;
- reads evaluator metadata;
- creates new representation primitives;
- adds unreported relations;
- uses a dynamically expanded feature language;
- retrieves a held-out extension directly;
- bypasses the declared representation interface.

Such a result cannot be counted as evidence that M1 alone solved the problem.

---

# 23. Model-Internal Discovery of an R1 Candidate

Suppose a model internally computes a structure `c`.

If:

    c ∈ Closure(R₀)

then it is baseline computation.

If:

    c ∉ Closure(R₀)

then the model has crossed the declared representation boundary.

The experiment must then be classified as representation extension or benchmark-contract violation, depending on whether the extension was explicitly declared.

It cannot be counted as a pure model-family comparison.

---

# 24. R₀ Must Not Be Tuned Against UNKNOWN

The benchmark designer must not:

1. observe UNKNOWN's failures;
2. alter R₀;
3. redefine the closure;
4. create an R1 condition;
5. evaluate UNKNOWN again;
6. report the result as independent evidence.

This would constitute benchmark adaptation and invalidate the scientific comparison.

R₀ must be frozen before final evaluation.

---

# 25. Independent R₀ Justification

R₀ must be justified using:

- the public observation contract;
- the scientific domain represented by the benchmark;
- explicitly available typed primitives;
- an independently specified operator vocabulary;
- explicit composition semantics.

R₀ must not be justified by:

- UNKNOWN's architecture;
- UNKNOWN's observed weaknesses;
- which extension produces the largest performance gain;
- a desired experimental result.

---

# 26. Closure Boundary Policy

The following rules define the baseline closure policy.

### R0-C1 — Explicit primitives

Every primitive belongs to the declared typed vocabulary V₀.

### R0-C2 — Explicit operators

Every derivation uses an operator in O₀.

### R0-C3 — Typed composition

Only type-valid compositions are admitted.

### R0-C4 — Finite terms

Representations are finite constructions.

### R0-C5 — No unrestricted computation

Arbitrary functions over raw observations are excluded.

### R0-C6 — No hidden inputs

Closure cannot depend on hidden environment or evaluator state.

### R0-C7 — Semantic equivalence

Semantically equivalent baseline structures count as members of the same baseline closure.

### R0-C8 — Pre-evaluation freeze

Closure semantics are frozen before final UNKNOWN evaluation.

### R0-C9 — No performance-based closure

Observed benchmark performance cannot redefine expressibility.

### R0-C10 — Model isolation

Model-family expansion cannot modify Closure(R₀).

---

# 27. Scientific Consequence

The resulting hierarchy is:

    Public Information
            │
            ▼
       Baseline R₀
            │
            ▼
      Closure(R₀)
            │
            ▼
      Model Family
            │
            ▼
          Output

A representation extension changes:

    Closure(R₀) → Closure(R₁)

A model-family change changes:

    F(M₀) → F(M₁)

A parameter update changes:

    θ_current → θ_new

These are three different interventions on the scientific system.

# 28. Controlled Failure Taxonomy

### R0 — Representation-Sufficient Control

    R₀ sufficient
    M₀ sufficient
    θ correct/learnable

### P1 — Parameter Failure

    R₀ sufficient
    M₀ sufficient
    θ incorrect

### M1 — Model-Family Failure

    R₀ sufficient
    M₀ insufficient
    M₁ sufficient
    R₀ unchanged

### R1 — Representation-Level Inadequacy

    R₀ insufficient
    M₀ insufficient over R₀
    M₁ insufficient over R₀
    valid R₁ exists

### N1 — Non-Identifiable / Insufficient Evidence

    multiple materially different explanations
    remain compatible with the permitted evidence

### X1 — Noise / Stochastic Variation

    R₀ sufficient
    model family sufficient
    stochastic variation causes errors

### T1 — Unseen-Context Transfer

Transfer is an evaluation property rather than a failure class.

---

# 29. R1 Proof Obligations

A benchmark R1 condition must establish, before UNKNOWN final evaluation:

### R1-A — Public Recoverability

The relevant distinction is available through the public interaction boundary.

### R1-B — Baseline Collision

There exist relevant histories such that:

    R₀(H₁) = R₀(H₂)

while the required outcome differs.

### R1-C — Model-Family Independence

Changing the model family while retaining R₀ cannot resolve the collision.

### R1-D — Valid Extension

A declared extension R₁ can distinguish the relevant histories.

### R1-E — Scientific Consequence

The distinction has measurable consequences under the benchmark's predefined evaluation protocol.

### R1-F — No Leakage

The distinction is not recoverable from condition metadata, naming, seeds, timing artifacts, evaluator information, or other forbidden channels.

---

# 30. Evidence Ordering

Representation-level claims should be evaluated in this order:

    1. Structural definition
    2. Public recoverability
    3. Baseline representation collision
    4. Parameter recovery attempt
    5. Model-family recovery attempt
    6. Candidate extension
    7. Prediction
    8. Intervention
    9. Falsification
    10. Transfer

Performance improvement is evidence after structural validity, not the definition of representation failure.

---

# 31. Research Decision

D.5.3.1 establishes the following decision:

> The benchmark will define model families as mapping classes over a fixed representation closure. The baseline closure will be generated by a frozen, finite, typed representation grammar with explicitly declared primitives, operators, composition rules, and semantic-equivalence rules. Unrestricted computation over raw observations and hidden information are outside the baseline representation language. Model-family expansion may change the mapping class but may not change the representation closure. Representation-level inadequacy will be constructed using explicit baseline representation collisions rather than inferred from model performance alone.

## D.5.3.1 Model-Family Semantics & Recovery Capability Boundary

### Status

### 34.1 Research Objective

Determine how the executable benchmark will distinguish:

- parameter failure;
- model-family failure;
- representation-level inadequacy;
- representation extension.

The principal threat is allowing model-family expansion to silently alter the representation boundary.

### 34.2 Decision

The benchmark separates three levels:

```text
Representation
      ↓
Model family
      ↓
Parameters
```

A model-family change may alter only the mapping class.

A parameter change may alter only parameter values.

A representation extension changes the admissible representation closure.

### 34.3 Model-Family Contract

A model family is defined as a class of admissible mappings from a fixed representation to benchmark outcomes.

Conceptually:

    F(M) = admissible mapping class

with:

    M₀ : Closure(R₀) → Y
    M₁ : Closure(R₀) → Y

where M₁ may have a richer mapping class than M₀.

The representation remains fixed.

### 34.4 Model-Family Invariant

A valid model-family comparison may not:

- access raw observations outside R₀;
- access hidden state;
- access evaluator truth;
- introduce new primitives;
- introduce new relations;
- dynamically expand the representation language;
- bypass the representation interface.

If it does, the comparison is not a pure model-family experiment.

### 34.5 Baseline Closure Contract

The baseline representation is:

    R₀ = (V₀, T₀, O₀, C₀)

Closure is:

    Closure(R₀)
      = all finite, well-typed structures derivable
        from V₀ using O₀ under C₀
        and the declared semantic-equivalence rules.

The closure is determined before UNKNOWN's final evaluation.

### 34.6 Why Explicit Closure Is Required

Without an explicit closure definition, the benchmark could incorrectly classify:

- difficult computation;
- optimization failure;
- model-family failure;
- search failure;

as representation discovery.

Closure provides the reference boundary against which such claims can be tested.

### 34.7 Rejected Closure Policies

**34.7.1 Arbitrary Depth-Only Boundary**

Rejected:

    R₀ = expressions of depth <= N
    R₁ = expressions of depth N+1

unless an independent scientific reason exists for that boundary.

Composition depth alone does not establish representational novelty.

**34.7.2 Performance-Defined Closure**

Rejected:

    UNKNOWN cannot solve X
    therefore X is outside R₀

This is circular.

**34.7.3 Unrestricted Universal Function**

Rejected:

    R₀ includes arbitrary function(raw_observation)

This collapses representation into unrestricted computation.

### 34.8 Expressibility vs Discoverability

The benchmark must distinguish:

    Expressible(R₀, c)

from:

    Discoverable(UNKNOWN, c)

A structure may be expressible but not discovered.

That is not R1 evidence.

This distinction protects the benchmark from turning search difficulty into representation inadequacy.

### 34.9 Semantic Equivalence

Syntactic difference is not sufficient for representation novelty.

Two different expressions may represent the same structure.

Therefore the executable benchmark must eventually define semantic-equivalence rules appropriate to the finite typed representation language.

Potential mechanisms include:

- canonicalization;
- symbolic normalization;
- finite-domain equivalence;
- typed structural equivalence;
- semantic witnesses.

Unresolved equivalence must not automatically be treated as novelty.

### 34.10 Internal Computation

A model may compute arbitrary intermediate quantities permitted by its model-family contract.

Such internal quantities do not automatically constitute representation extensions.

If a computed quantity belongs to Closure(R₀), it remains baseline computation.

If it does not belong to Closure(R₀), then the model has crossed the representation boundary and the experiment must be treated as an extension or contract violation.

### 34.11 R1 Constructive Witness

The central R1 construction is an R₀ collision.

Find:

    H₁, H₂

such that:

    R₀(H₁) = R₀(H₂)

but:

    Y(H₁) ≠ Y(H₂)

No deterministic downstream mapping operating solely on R₀ can distinguish the two histories.

A valid extension must produce:

    R₁(H₁) ≠ R₁(H₂)

This provides a constructive representation-level witness.

### 34.12 Failure Taxonomy

| Condition | Representation | Model Family | Parameters |
|---|---|---|---|
| R0 | sufficient | sufficient | correct/learnable |
| P1 | sufficient | sufficient | incorrect |
| M1 | sufficient | insufficient | irrelevant |
| R1 | insufficient | insufficient over R₀ | irrelevant |
| R1 + extension | extended | sufficient | learnable |

### 34.13 P1 Boundary

P1 requires:

    Recoverable(M₀, R₀, f*) = true

but current parameters are incorrect.

A valid parameter update can recover the target without changing:

- R₀;
- model family;
- representation closure.

### 34.14 M1 Boundary

M1 requires:

    Recoverable(M₀, R₀, f*) = false
    Recoverable(M₁, R₀, f*) = true

while R₀ remains sufficient.

Therefore M1 demonstrates mapping-class insufficiency rather than representation insufficiency.

### 34.15 R1 Boundary

R1 requires:

    R₀(H₁) = R₀(H₂)
    Y(H₁) ≠ Y(H₂)

and a valid extension:

    R₁(H₁) ≠ R₁(H₂)

with the relevant distinction publicly recoverable.

This prevents a richer model family from being incorrectly credited with solving a representation problem.

### 34.16 Anti-Circularity Controls

The benchmark must prevent:

- changing R₀ after seeing UNKNOWN failures;
- defining candidates based on performance;
- defining representation novelty by benchmark improvement;
- allowing evaluator truth into model-family experiments;
- treating internal model features as automatic concepts;
- treating expression depth alone as semantic novelty.

### 34.17 Freeze Requirement

Before final UNKNOWN evaluation, freeze:

- V₀
- T₀
- O₀
- C₀
- semantic-equivalence policy
- serialization/canonicalization policy

The final evaluation must not alter these definitions.

### 34.18 Evidence Ordering

The intended order is:

    1. Structural definition
    2. Public recoverability
    3. R₀ collision
    4. Parameter recovery attempt
    5. Model-family recovery attempt
    6. Extension
    7. Prediction
    8. Intervention
    9. Falsification
    10. Transfer

The ordering prevents performance from becoming the definition of representation failure.

### 34.19 Scientific Risks Remaining

The following remain open for executable benchmark design:

- **RISK-1 — Semantic equivalence**: How can equivalence be tested safely and reproducibly?
- **RISK-2 — Primitive scope**: Which primitives belong in V₀ independently of the target conditions?
- **RISK-3 — Operator scope**: Which operators belong in O₀ without making closure trivial or artificially weak?
- **RISK-4 — Composition semantics**: How should C₀ constrain valid compositions?
- **RISK-5 — Collision construction**: How should R1 collision witnesses be generated automatically?
- **RISK-6 — Model-family contracts**: How should M₀ and M₁ be specified so that their information boundaries remain auditable?
- **RISK-7 — Extension validity**: How should candidate extensions be serialized, executed, compared, and validated?

These are implementation/design questions, not reasons to weaken the D.5.3.1 conceptual contract.
