# Project UNKNOWN — S0.4 Environment Schema

**Status:** Working implementation schema
**Sprint:** Sprint 0 — S0.4
**Date:** 2026-09-23
**Purpose:** Translate the S0.4 synthetic-environment scientific contract into explicit runtime data boundaries and schemas.

---

# 1. Purpose

This document defines the concrete schema boundary between:

1. environment generation;
2. public observations;
3. actions and interventions;
4. hidden benchmark truth;
5. evaluation artifacts.

The primary architectural requirement is:

> UNKNOWN must receive only the information permitted by the experimental protocol.

The implementation must make accidental access to hidden benchmark information difficult by construction.

---

# 2. Schema Layers

The environment is divided into three conceptual layers:

```text
PUBLIC
    ↓
information available to UNKNOWN

HIDDEN
    ↓
benchmark construction and ground truth

EVALUATION
    ↓
post-run scientific analysis
```

These layers must not be represented as one unrestricted object passed throughout the system.

---

# 3. Public Layer

The public layer contains only information that UNKNOWN is permitted to access.

Conceptual contents:

```text
PublicEnvironment
├── observation
├── action interface
├── intervention interface
├── terminal status
└── safe episode metadata
```

The public layer must never contain:

* hidden benchmark condition;
* hidden concept labels;
* hidden causal graph;
* hidden target state;
* ground-truth candidate representation;
* evaluation labels;
* final test outcomes.

---

# 4. Hidden Layer

The hidden layer contains information required to construct and evaluate the benchmark.

Conceptual contents:

```text
HiddenEnvironment
├── hidden state
├── transition parameters
├── benchmark condition
├── intended structural relation
├── ground-truth representation
├── causal structure
└── evaluation-only annotations
```

The hidden layer must never cross the public runtime boundary.

---

# 5. Evaluation Layer

The evaluation layer contains artifacts generated after or independently from the UNKNOWN run.

Conceptual contents:

```text
EvaluationRecord
├── diagnosis comparison
├── prediction results
├── intervention results
├── falsification results
├── transfer results
├── complexity measurements
├── reproducibility metadata
└── ground-truth comparison
```

Evaluation code may access hidden truth.

UNKNOWN may not.

---

# 6. Environment Configuration

The environment configuration defines how an instance is generated.

Conceptual schema:

```text
EnvironmentConfig
├── environment_version
├── task_version
├── entity_count
├── episode_length
├── dynamics_config
├── observation_config
├── action_config
├── intervention_config
├── randomization_config
└── seed
```

Configuration must distinguish public configuration from evaluation-only configuration.

---

# 7. Environment Version

Every environment configuration has an immutable version identifier.

Example:

```text
unknown-relational-v0.1
```

Changing any scientific behavior requires a new version.

Changes requiring a new version include:

* transition equations;
* observation fields;
* action semantics;
* intervention semantics;
* task targets;
* representation primitives;
* benchmark condition definitions;
* evaluation thresholds.

---

# 8. Task Version

Every task definition receives an independent version identifier.

Example:

```text
task-relational-prediction-v0.1
```

A task version must define:

* prediction target;
* prediction horizon;
* metric;
* adequacy threshold;
* permitted model families;
* permitted representation;
* allowed actions;
* allowed interventions.

Task identifiers must not encode the hidden benchmark condition.

---

# 9. Entity Schema

A public entity may expose:

```text
EntityObservation
├── entity_id
├── entity_type
├── position
├── velocity
├── observable_attributes
└── timestamp
```

The exact fields are task-configurable.

Entity identifiers are opaque identifiers.

They must not encode:

* benchmark condition;
* entity role;
* target label;
* hidden state.

---

# 10. Position

The initial environment uses bounded continuous position coordinates.

Conceptually:

$$
p_i=(x_i,y_i)
$$

The coordinate system must be declared in the environment configuration.

Positions exposed to UNKNOWN must contain no hidden benchmark metadata.

---

# 11. Velocity

Velocity is represented as:

$$
v_i=(v_{x,i},v_{y,i})
$$

Velocity may be exposed when permitted by the task.

A task that hides velocity must not accidentally expose it through derived metadata.

---

# 12. Observable Attributes

Observable attributes are explicitly declared.

Examples include:

```text
attribute_a
attribute_b
surface_type
category
```

Attributes must be generated independently where necessary to prevent accidental shortcut correlations.

Any intentional correlation must be documented as part of the benchmark design.

---

# 13. Observation Schema

A public observation is conceptually:

```text
Observation
├── timestamp
├── entities[]
└── permitted_relations[]
```

Only fields explicitly declared by the task's observation configuration may be present.

---

# 14. Observation History

A trajectory may expose:

```text
ObservationHistory
├── observations[]
└── actions[]
```

The UNKNOWN representation layer may derive temporal features from this history if permitted.

The history must not contain hidden evaluation fields.

---

# 15. Relation Observation

A permitted primitive relation may contain:

```text
RelationObservation
├── source_entity
├── target_entity
├── relation_type
└── value
```

Examples include:

* distance;
* relative position;
* ordering.

The relation type must describe the observable primitive itself.

It must not encode a hidden higher-level concept.

---

# 16. Candidate Representation Boundary

A candidate representation is not part of the raw environment observation.

The conceptual flow is:

```text
Observation
    ↓
Current Representation
    ↓
Candidate Extension
    ↓
Model
```

This separation allows the experiment to determine whether the candidate itself contributes additional reusable structure.

---

# 17. Action Schema

Actions are typed requests from UNKNOWN to the environment.

Conceptually:

```text
Action
├── action_type
├── target_entity
├── parameters
└── timestamp
```

Invalid actions must be rejected.

The environment must not silently reinterpret malformed actions.

---

# 18. Intervention Schema

An intervention is distinct from ordinary action execution.

Conceptually:

```text
Intervention
├── intervention_type
├── target
├── value
├── timestamp
└── intervention_id
```

The intervention interface must expose only interventions explicitly permitted by the task.

---

# 19. Intervention Result

A public intervention result may contain:

```text
InterventionResult
├── intervention_id
├── resulting_observation
├── timestamp
└── terminal
```

It must not contain:

* causal effect labels;
* hidden state;
* benchmark condition;
* ground-truth expected outcome.

---

# 20. Safe Episode Metadata

The public episode metadata interface is intentionally restricted.

Safe metadata may include:

```text
PublicEpisodeMetadata
├── episode_id
├── environment_version
├── task_version
├── step_index
└── terminal
```

Metadata must not include:

* benchmark condition;
* hidden seed streams where they encode evaluation identity;
* hidden concept name;
* target variable name;
* ground-truth representation.

---

# 21. Hidden State Schema

The hidden state may contain:

```text
HiddenState
├── true_entity_state
├── hidden_relations
├── environment_parameters
├── transition_state
└── hidden_variables
```

This schema is evaluation-only.

The public runtime must not hold a reference to the hidden state where avoidable.

---

# 22. Benchmark Condition

The benchmark condition is hidden.

Conceptually:

```text
BenchmarkCondition
├── PARAMETER_FAILURE
├── MODEL_FAMILY_FAILURE
├── REPRESENTATION_FAILURE
├── LANGUAGE_INSUFFICIENCY
└── INFORMATION_UNAVAILABLE
```

This value belongs exclusively to the evaluation layer.

It must never appear in public task metadata.

---

# 23. Ground-Truth Representation

The hidden benchmark may define a reference representation:

```text
GroundTruthRepresentation
├── primitives
├── derived relations
├── temporal relations
└── intended equivalence class
```

UNKNOWN does not receive this object.

It is used only for post-hoc analysis.

---

# 24. Ground-Truth Equivalence

Evaluation may compare an UNKNOWN candidate with an equivalence class rather than requiring exact structural identity.

Conceptually:

```text
Candidate
    ↓
Empirical evaluation
    ↓
Equivalent / non-equivalent
```

The equivalence decision must be based on the frozen evaluation suite.

---

# 25. Evaluation Record

An evaluation record is created independently of the public environment interface.

Conceptual schema:

```text
EvaluationRecord
├── experiment_id
├── environment_version
├── task_version
├── seed
├── diagnosis
├── prediction_results
├── intervention_results
├── falsification_results
├── transfer_results
├── candidate_results
├── complexity_results
└── reproducibility_results
```

Ground truth may be joined to this record after UNKNOWN execution.

---

# 26. Experiment Identity

Every experiment receives a unique experiment identifier.

The identifier must not reveal the benchmark condition.

For example:

```text
EXP-000001
EXP-000002
EXP-000003
```

is preferable to:

```text
REPRESENTATION-FAILURE-001
```

---

# 27. Seed Schema

The experiment records all randomness required for replay.

Conceptual schema:

```text
SeedRecord
├── global_seed
├── environment_seed
├── initial_state_seed
├── intervention_seed
└── auxiliary_seeds
```

If one deterministic master seed is used to derive sub-seeds, the derivation method must be documented.

---

# 28. Replay Contract

A replayable experiment requires:

```text
EnvironmentConfig
+
TaskConfig
+
SeedRecord
+
InitialState
+
ActionSequence
```

to reproduce the same environment trajectory within declared numerical tolerance.

---

# 29. Numerical Tolerance

The environment must define tolerance for deterministic replay.

For a numerical quantity \(x\), replay may require:

$$
|x_{run1}-x_{run2}|\leq\epsilon
$$

where \(\epsilon\) is defined by the environment version.

The tolerance must not be selected after observing experimental results.

---

# 30. Public API

The first runtime environment should expose a narrow interface:

```text
reset(config, seed)
observe()
step(action)
intervene(intervention)
is_terminal()
episode_metadata()
```

The implementation may use additional internal methods.

Only the public API is available to UNKNOWN.

---

# 31. Reset Contract

`reset()` initializes an episode.

It must:

1. construct the permitted initial state;
2. initialize deterministic random streams;
3. initialize episode identity;
4. prepare the first observation;
5. prevent hidden state from entering the public object.

The reset response must contain only public information.

---

# 32. Observe Contract

`observe()` returns the current public observation.

It must never expose:

* hidden state;
* benchmark condition;
* ground-truth representation;
* evaluation labels.

The result must be serializable independently from the hidden environment state.

---

# 33. Step Contract

`step(action)` advances the environment.

Conceptually:

```text
step(action)
    ↓
validate action
    ↓
apply action
    ↓
advance transition
    ↓
generate public observation
    ↓
return public result
```

The returned result must contain no hidden evaluation fields.

---

# 34. Intervention Contract

`intervene(intervention)` applies an explicitly permitted intervention.

The implementation must:

1. validate intervention type;
2. validate target;
3. validate value;
4. apply the intervention;
5. advance or evaluate the environment according to the task contract;
6. return only permitted observations.

---

# 35. Terminal Contract

`is_terminal()` reports whether the episode has reached its declared terminal condition.

Terminal status itself is public.

The reason for termination may be hidden if revealing it would leak benchmark information.

---

# 36. Public/Hidden Object Separation

The implementation should avoid patterns such as:

```text
public_environment.hidden_state
```

or:

```text
observation.environment
```

where UNKNOWN can traverse object references to hidden data.

Instead, public data should be explicit immutable data structures or serialized values.

---

# 37. Hidden/Evaluation Access

Hidden and evaluation functionality should require explicit internal interfaces.

Conceptually:

```text
PublicEnvironment
        │
        X
        │
HiddenEnvironment
        │
        ▼
EvaluationHarness
```

UNKNOWN receives only `PublicEnvironment`.

The evaluation harness may access both public execution records and hidden truth.

---

# 38. Information-Unavailable Schema

An information-unavailable benchmark condition must specify:

```text
UnavailableCondition
├── hidden_variable
├── excluded_from_observation
├── proof_or_construction_of_indistinguishability
└── evaluation_target
```

The `hidden_variable` and proof are evaluation-only.

UNKNOWN receives no indication that the information is unavailable.

---

# 39. Representation-Failure Schema

A representation-failure condition must specify:

```text
RepresentationFailureCondition
├── observable_source
├── excluded_from_current_representation
├── permitted_extension
├── admissible_model_families
├── adequacy_threshold
└── evaluation_target
```

The distinction is:

```text
available through observation
        +
absent from current representation
        +
expressible by extension
```

---

# 40. Model-Family-Failure Schema

A model-family-failure condition must specify:

```text
ModelFamilyFailureCondition
├── current_representation
├── initial_model_family
├── stronger_model_family
├── optimization_budget
└── adequacy_threshold
```

Both model families must receive the same representation.

---

# 41. Parameter-Failure Schema

A parameter-failure condition must specify:

```text
ParameterFailureCondition
├── representation
├── model_family
├── initial_parameter_state
├── optimization_procedure
└── adequacy_threshold
```

The representation and model family remain fixed.

---

# 42. Language-Insufficiency Schema

A language-insufficiency condition must specify:

```text
LanguageInsufficiencyCondition
├── observation_source
├── current_representation
├── extension_language
├── excluded_structure
└── evaluation_target
```

The intended candidate must be outside the declared extension language.

---

# 43. Public Configuration

Configuration fields accessible to UNKNOWN may include:

* allowed observation fields;
* permitted action types;
* permitted intervention types;
* public environment dimensions;
* episode limits;
* permitted representation primitives.

Public configuration must not encode the hidden benchmark condition.

---

# 44. Hidden Configuration

Hidden configuration may contain:

* benchmark condition;
* hidden variables;
* ground-truth representation;
* target construction;
* evaluation labels;
* equivalence annotations.

Hidden configuration is inaccessible to UNKNOWN.

---

# 45. Evaluation Configuration

Evaluation configuration may contain:

* final thresholds;
* hidden labels;
* equivalence tests;
* diagnostic ground truth;
* transfer annotations;
* statistical comparison parameters.

Evaluation configuration is loaded only by the evaluation harness.

---

# 46. Serialization Boundary

Public observations must be serializable without serializing hidden environment state.

The serialization format should contain only explicitly declared public schema fields.

This provides an additional leakage-control mechanism.

---

# 47. Logging Boundary

UNKNOWN-facing logs must not contain:

* hidden benchmark condition;
* hidden state;
* intended concept names;
* evaluation labels.

Evaluation logs may contain these values when necessary.

Logging configuration must therefore distinguish:

```text
public_run.log
evaluation.log
```

or an equivalent access-controlled separation.

---

# 48. Error Boundary

Exceptions returned through the public interface must not reveal hidden implementation information.

For example, an invalid action should produce a generic validation error rather than an error revealing:

```text
the hidden target variable
```

or:

```text
the current benchmark condition
```

---

# 49. Test Boundary

Unit tests may access hidden state when verifying environment correctness.

However, tests used to evaluate UNKNOWN must use only the public interface.

This distinction must be maintained in the test architecture.

---

# 50. Transfer Schema

A transfer environment is defined by:

```text
TransferConfig
├── source_environment_version
├── changed_dimensions
├── preserved_structure
├── seed
└── evaluation_scope
```

The changed dimensions must be known to the evaluation system.

UNKNOWN receives only the resulting public environment.

---

# 51. Intervention Record

The evaluation harness records:

```text
InterventionRecord
├── intervention_id
├── experiment_id
├── target
├── intervention_value
├── pre_intervention_state
├── predicted_outcome
├── observed_outcome
└── error
```

Hidden state fields are evaluation-only.

---

# 52. Candidate Record

UNKNOWN candidate provenance should record:

```text
CandidateRecord
├── candidate_id
├── expression
├── primitive_dependencies
├── construction_history
├── discovery_trigger
├── hypothesis
├── predicted_consequences
├── falsification_conditions
└── complexity
```

The candidate record must not contain hidden benchmark labels.

---

# 53. Candidate Provenance

Every candidate must be traceable to the evidence that caused it to be proposed.

At minimum:

```text
candidate
    ↓
trigger evidence
    ↓
hypothesis
    ↓
construction
    ↓
validation
```

This allows later analysis of whether the candidate emerged from systematic failure rather than arbitrary search.

---

# 54. Configuration Immutability

Once a final experiment begins, the following must be immutable:

* environment version;
* task version;
* observation language;
* extension language;
* model-family set;
* complexity budget;
* evaluation thresholds;
* seed.

A change creates a new experiment configuration.

---

# 55. Schema Validation

Every serialized public object must be validated against its declared schema.

At minimum validate:

* required fields;
* field types;
* allowed enumerations;
* numeric ranges;
* identifier format;
* absence of forbidden fields.

---

# 56. Leakage Invariants

The implementation must enforce these invariants:

### Invariant 1

Public observations contain no hidden benchmark condition.

### Invariant 2

Public metadata contains no hidden concept name.

### Invariant 3

Public API responses contain no ground-truth labels.

### Invariant 4

UNKNOWN cannot traverse public objects to hidden state.

### Invariant 5

Final evaluation data cannot flow backward into candidate generation.

### Invariant 6

Information-unavailable cases cannot be labeled as representation-discovery successes.

---

The eventual runtime package should conceptually separate:

```text
environment/

├── dynamics/
├── hidden/
├── evaluation/
└── schemas/
```

The exact Python module structure will be finalized during implementation.

# 59. Schema Acceptance

The schema is acceptable only if:

$$
Public\ Access \cap Hidden\ Truth = \varnothing
$$

for all information prohibited by the experimental protocol.

The implementation must enforce this boundary rather than relying only on developer discipline.

---

# 60. Next Implementation Step

After this schema is reviewed, implementation begins with the smallest environment components:

```text
schemas
    ↓
deterministic dynamics
    ↓
public observation interface
    ↓
hidden benchmark generator
    ↓

tests
```

The first implementation will not contain UNKNOWN's discovery algorithm.

It will only establish a scientifically controlled environment in which UNKNOWN can later operate.
