# S0.5-D.5.2 — World-Family Design

**Project:** Project UNKNOWN — Autonomous Concept Formation & Model Discovery
**Stage:** S0.5-D.5.2
**Status:** Complete — research specification
**Implementation status:** Not implemented
**Depends on:** S0.5-D.4 Controlled Benchmark Contract, S0.5-D.5.1 Baseline Representation Contract

---

## 1. Purpose

S0.5-D.5.2 defines the world-family architecture used to instantiate controlled benchmark conditions for Project UNKNOWN.

The objective is to establish a world-generating system capable of producing:

- R0 — representation-sufficient control;
- P1 — parameter failure;
- M1 — model-family failure;
- R1 — representation-level inadequacy;
- N1 — non-identifiable / insufficient-evidence conditions;
- X1 — stochastic/noise conditions;
- T1 — unseen-context transfer evaluation.

The design must preserve the scientific distinctions established in D.4 and D.5.1.

In particular:

> A benchmark condition must differ because of a controlled structural property of the generated world, not because the environment exposes its condition label or because the condition is encoded through superficial artifacts.

---

## 2. Scientific Principle

The benchmark should use shared world-generating machinery rather than implementing each failure class as an unrelated environment.

The preferred structure is:

```text
Shared World Family
        ↓
Controlled configuration
        ↓
World instance
        ↓
Public observation boundary
        ↓
UNKNOWN
```

Private evaluator truth remains separate:

```text
PRIVATE WORLD TRUTH
        ↓
    EVALUATOR
        ↓ observes
PUBLIC ENVIRONMENT
        ↓
     UNKNOWN
```

The condition itself is therefore a property of the generated world and experiment configuration, not public metadata.

---

## 3. World Family vs Condition

A world family defines a class of generative mechanisms.

A condition defines a controlled instantiation of that family.

These concepts must not be conflated.

A single world family should be capable of producing multiple conditions where scientifically appropriate.

For example:

```text
World Family
    │
    ├── R0 configuration
    ├── P1 configuration
    ├── M1 configuration
    ├── R1 configuration
    ├── N1 configuration
    └── X1 configuration
```

This is preferred over implementing:

```text
R0Environment
P1Environment
M1Environment
R1Environment
...
```

as unrelated systems.

The latter creates unnecessary opportunities for condition-specific shortcuts.

---

## 4. Minimal Core World Family

The core benchmark family is defined as a:

> typed relational dynamical world

The family contains:

- entities;
- typed state;
- observable and hidden variables;
- relations;
- transition dynamics;
- ordinary actions;
- interventions;
- observations;
- optional controlled stochastic processes.

Conceptually:

```text
W = (E, X, R, F, G, I, ξ)
```

where:

- E = entities;
- X = state variables;
- R = relations;
- F = transition mechanism;
- G = observation function;
- I = intervention operators;
- ξ = stochastic component.

This is a conceptual world model, not yet an implementation API.

---

## 5. World State

A complete world state contains all variables required by the generator and evaluator.

Conceptually:

```text
S_t = (
    entities,
    observable_state,
    hidden_state,
    relations,
    mechanism_state,
    stochastic_state
)
```

The complete state may contain information unavailable to UNKNOWN.

The complete state is therefore evaluator/private information unless an individual component is explicitly exposed through the public observation contract.

---

## 6. Entity Model

Entities are generic and semantically neutral.

Conceptual identifiers include:

```text
entity_0
entity_1
entity_2
...
```

Entity identity must not encode semantic roles.

The baseline world may contain state such as:

- position;
- velocity;
- existence;
- observable scalar attributes;
- observable categorical attributes.

Future world-family specifications may extend this list only through explicit benchmark contracts.

Semantic identifiers such as:

```text
predator
prey
leader
target
cause
agent
```

are forbidden unless that semantic role is itself explicitly public in the benchmark.

---

## 7. Observable State

The public observation boundary may expose:

- entity identities;
- publicly observable entity state;
- explicitly observable relations;
- action outcomes;
- intervention outcomes;
- permitted time information;
- explicitly permitted task feedback.

The observation function is conceptually:

```text
O_t = G(S_t)
```

where:

- S_t = complete world state;
- O_t = public observation.

The observation function must be declared independently of UNKNOWN's implementation.

---

## 8. Hidden State

The world family may contain hidden variables.

Examples include:

- hidden mechanism state;
- hidden regime;
- internal dynamics variables;
- unobservable relations;
- generator state;
- private mechanism parameters.

Hidden information does not automatically constitute R1.

A hidden variable may instead produce:

- N1;
- ordinary partial observability;
- stochastic uncertainty;
- or a representation-level condition if the relevant distinction is publicly recoverable but cannot be represented under R0.

The benchmark must therefore distinguish:

```text
hidden
    ≠
representation-inadequate
```

---

## 9. Dynamics

The world transition mechanism is conceptually:

```text
S_(t+1) = F(S_t, A_t, I_t, θ, ξ_t)
```

where:

- S_t = current world state;
- A_t = ordinary action;
- I_t = intervention, if present;
- θ = world mechanism parameters;
- ξ_t = stochastic component.

The deterministic core should be used for initial representation-failure construction whenever possible.

Stochastic variation should be introduced separately through X1 controls.

This prevents noise from being confused with structural inadequacy.

---

## 10. Ordinary Actions and Interventions

Ordinary actions and interventions remain distinct.

**Ordinary action**

An action is part of the normal environment interaction process.

**Intervention**

An intervention deliberately modifies a selected part of the world state or mechanism according to the benchmark's intervention contract.

Interventions may include:

- state-position replacement;
- velocity replacement;
- entity removal;
- future explicitly defined intervention types.

UNKNOWN receives the observable consequences of its interaction.

It does not receive evaluator interpretation of those consequences.

---

## 11. Public Interaction Contract

The world-family interface must preserve a stable public contract across structurally different world families.

Conceptually:

```text
observe
act
intervene
```

The exact executable API remains a later implementation decision.

The scientific requirement is that UNKNOWN should not receive a different diagnostic interface for each condition.

The same public contract should be used whenever the corresponding operation is scientifically valid.

---

## 12. Core R0 Condition

R0 is the representation-sufficient negative control.

Required properties:

- R0 representation sufficient
- selected model family sufficient
- parameters correct or learnable

The purpose is to establish normal operation without requiring representation extension.

R0 also functions as a false-positive control.

If UNKNOWN repeatedly proposes representation extensions under R0 conditions, the discovery mechanism may be over-triggering.

---

## 13. P1 Parameter-Failure Condition

P1 keeps the representation and model family sufficient while deliberately changing the parameter state.

Conceptually:

```text
R0 sufficient
M0 sufficient
θ_current ≠ θ*
```

A valid parameter setting exists within the baseline representation/model family.

The correct recovery path is therefore parameter updating rather than representation extension.

P1 is a primary negative control against interpreting systematic prediction error as representation failure.

---

## 14. M1 Model-Family-Failure Condition

M1 keeps the representation sufficient but makes the selected model family insufficient.

Conceptually:

```text
R0 sufficient
M0 insufficient
M1 sufficient
```

The required structure remains available through R0.

A richer or otherwise appropriate model family can solve the condition without changing the representation.

M1 prevents UNKNOWN from interpreting every failure of its current model as a missing representation.

---

## 15. R1 Representation-Level Inadequacy

R1 is defined through a representation collision rather than by naming a missing feature.

Let H denote the permitted public interaction history.

A clean R1 condition requires a pair:

```text
H1
H2
```

such that:

```text
R0(H1) = R0(H2)
```

while the required outcome differs:

```text
Y(H1) ≠ Y(H2)
```

Therefore any model operating solely over R0 receives identical representation input for cases requiring different outcomes.

No parameter setting or model-family expansion downstream of R0 can recover a distinction that R0 has collapsed.

A valid representation extension C must produce:

```text
R1 = Extend(R0, C)
```

such that:

```text
R1(H1) ≠ R1(H2)
```

and the required outcome becomes expressible.

This provides a constructive R1 witness.

---

## 16. R1 Is Not Defined by Feature Naming

The benchmark must not define R1 merely as:

> "R0 does not contain feature X"

or:

> "R1 contains a ternary relation"

A feature not being explicitly named does not establish representation inadequacy.

The correct question is:

> Is the required distinction expressible within the complete declared R0 language?

Therefore:

```text
not named
    ≠
not expressible
```

and:

```text
higher arity
    ≠
automatic representation novelty
```

---

## 17. Representation Collision

R0 induces an equivalence relation over permitted histories:

```text
H1 ~0 H2
iff
R0(H1) = R0(H2)
```

A representation-level inadequacy exists when two histories remain equivalent under R0 while requiring different predictions or intervention outcomes.

An extension is useful when it refines the equivalence:

```text
H1 ~0 H2
```

but:

```text
H1 not equivalent to H2 under R1
```

because:

```text
R1(H1) ≠ R1(H2)
```

This makes representation discovery a problem of representation refinement.

---

## 18. R1 Recovery Ladder

R1 construction must use a recovery ladder:

```text
Level 0
R0 + baseline model

Level 1
R0 + parameter optimization

Level 2
R0 + permitted model-family expansion

Level 3
R1 + appropriate model family
```

A clean R1 condition should resist Levels 0–2 and become expressible at Level 3.

The benchmark must not declare R1 merely because a particular UNKNOWN implementation performs poorly.

---

## 19. R1 Public Recoverability

The missing distinction must be recoverable from information legitimately available through the public interaction boundary.

Therefore:

```text
public evidence exists
        ↓
R0 collapses relevant histories
        ↓
extension can recover distinction
```

A completely unobservable hidden variable does not automatically qualify as R1.

If multiple explanations remain compatible with public evidence, the condition may instead be N1.

---

## 20. Candidate R1 Structure

A primary candidate for the first executable R1 condition is a bounded relational abstraction.

A concrete instance may involve a higher-order relational motif, but the scientific object is not "ternary-ness."

The relevant property is:

> The required structural distinction is outside the declared expressibility class of R0.

A candidate may be represented as:

```text
C = structural_motif
```

with explicit:

- construction rule;
- supporting evidence;
- predictions;
- intervention predictions;
- falsification conditions;
- transfer behavior;
- complexity characteristics.

A new name alone is not evidence of a new representation.

---

## 21. Why Higher-Order Relations Remain a Useful Construction

A higher-order relational motif is useful because it can provide a concrete implementation of the representation-collision principle.

However, the benchmark must first establish:

```text
Q not expressible under R0
```

rather than merely:

```text
Q not explicitly named by R0
```

If the existing R0 operators can reconstruct Q, the condition is not R1.

This distinction is mandatory.

---

## 22. R0 Closure Requirement

The executable R0 language must have explicit semantics for:

- primitives;
- types;
- operators;
- composition;
- temporal access;
- representation equality/equivalence.

The implementation must make it possible to determine whether two public histories map to the same baseline representation.

Therefore R0 cannot remain an informal feature list.

It must eventually become an executable representation contract.

---

## 23. N1 Condition

N1 represents non-identifiability or insufficient evidence.

Construct:

```text
H1
H2
```

or competing mechanisms:

```text
M_A
M_B
```

such that the permitted experimental protocol cannot distinguish them.

Conceptually:

```text
P(observations | M_A)
=
P(observations | M_B)
```

under the permitted protocol, or the observations remain materially compatible with both explanations.

UNKNOWN should be permitted to return:

```text
UNCERTAIN
```

without being forced to invent a representation.

If an intervention can distinguish the explanations, the benchmark may permit such an intervention as an information-seeking experiment.

N1 must not be constructed by simply hiding information that an appropriate R1 extension could recover from public evidence.

---

## 24. X1 Condition

X1 introduces controlled stochastic variation while keeping the underlying representation and model family sufficient.

Conceptually:

```text
x_(t+1) = f(x_t) + ξ_t
```

where ξ_t follows a declared stochastic process.

The purpose is to distinguish:

> systematic structural error

from:

> expected stochastic variation

X1 should initially use controlled noise characteristics so that its effect can be independently evaluated.

---

## 25. T1 Transfer Condition

T1 is primarily an evaluation property rather than an independent failure class.

A representation extension discovered in one context should be evaluated under a structurally different context.

Transfer may vary:

- entity identities;
- initial conditions;
- parameters;
- arrangements;
- mechanism instances;
- superficial distributions;
- composition;
- world-family structure.

A successful local patch must not automatically be treated as a reusable abstraction.

When the scientific claim is reusability beyond one generator family, evaluation should include at least one structurally distinct held-out family.

---

## 26. Core Family and Held-Out Family

One typed relational dynamical family is sufficient for constructing the core controlled conditions.

However, one family is not sufficient for the complete scientific evaluation.

Therefore the benchmark architecture is:

```text
CORE FAMILY
    ↓
R0 / P1 / M1 / R1 / N1 / X1
    ↓
candidate extension
    ↓
STRUCTURALLY DISTINCT HELD-OUT FAMILY
    ↓
T1 / transfer evaluation
```

The held-out family exists to distinguish reusable abstraction from generator-specific memorization.

The number and exact design of held-out families remain implementation/design questions.

---

## 27. Structural Variation

World instances must vary along controlled dimensions.

Possible dimensions include:

**Entity variation**
- entity count;
- identity permutation;
- arrangement.

**State variation**
- initial positions;
- velocities;
- observable attributes;
- initial relational configurations.

**Parameter variation**
- interaction strengths;
- thresholds;
- rates;
- other declared mechanism parameters.

**Mechanism variation**
- independent mechanism instances within a family;
- structurally related mechanisms;
- controlled mechanism composition.

**Context variation**
- superficial environmental changes;
- observation distributions;
- irrelevant attributes.

**Intervention variation**
- target;
- intervention value;
- intervention sequence.

**Noise variation**
- declared stochastic process;
- controlled magnitude;
- seed.

Variation must not expose condition identity.

---

## 28. Matched Worlds

Matched world construction is required where scientifically appropriate.

Two worlds may share:

- entity count;
- initial-state distribution;
- observable marginal distributions;
- action space;
- intervention availability;
- timing;
- noise characteristics;

while differing in the structural mechanism being tested.

The goal is:

```text
superficial statistics approximately matched
        +
structural mechanism different
```

This reduces shortcut classification.

---

## 29. Anti-Shortcut Requirements

Conditions must not be identifiable through superficial artifacts.

Forbidden shortcuts include encoding condition identity through:

- entity count;
- semantic IDs;
- fixed positions;
- fixed timing;
- intervention availability;
- unique observation lengths;
- distinctive noise levels;
- unique public metadata;
- world-family identifiers;
- exception messages;
- filesystem paths;
- seed values;
- evaluator annotations.

Where scientifically appropriate, distributions should overlap across conditions.

---

## 30. Condition Assignment Must Be Private

The following remain evaluator-private:

- condition ID;
- failure class;
- representation sufficiency;
- model-family sufficiency;
- parameter truth;
- canonical extension;
- benchmark seed;
- mechanism identity;
- expected failure type.

UNKNOWN may know:

- its own requested action;
- its own requested intervention;
- publicly returned consequences.

UNKNOWN must not receive evaluator interpretation of those events.

---

## 31. Intervention Compatibility

The same world family should support controlled intervention experiments where scientifically valid.

Intervention experiments may include:

- baseline observation;
- direct state perturbation;
- entity removal;
- repeated intervention;
- matched contrastive intervention;
- restoration/reversal where supported;
- cross-context intervention.

The benchmark must distinguish:

> independent matched trial

from:

> sequential trial with accumulated effects

Matched intervention comparisons require explicitly controlled initial conditions.

---

## 32. R1 Intervention Witness

For an R1 candidate, an intervention can provide additional evidence when it changes the proposed structural relation while holding other relevant variables controlled.

Conceptually:

```text
observe
    ↓
competing explanation
    ↓
select intervention
    ↓
observe consequence
    ↓
compare prediction
    ↓
update representation / uncertainty
```

Intervention outcomes are evidence.

They are not automatically proof that a missing concept exists.

---

## 33. Reproducibility

World-family generation must conform to the D.4 reproducibility contract.

Experiments should eventually identify:

```text
experiment_id
condition_id
scenario_id
trial_id
seed
configuration_id
```

The seed hierarchy should conceptually separate:

```text
master seed
├── world seed
├── scenario seed
├── trial seed
├── noise seed
└── evaluation seed
```

UNKNOWN's internal randomness should remain separate from environment and evaluator randomness.

Matched experiments should differ only in the declared experimental factor.

---

## 34. Deterministic R1 Construction

Initial R1 construction should prefer deterministic worlds or controlled deterministic subconditions.

This allows the evaluator to establish:

```text
R0(H1) = R0(H2)
```

and:

```text
Y(H1) ≠ Y(H2)
```

without stochastic ambiguity.

Stochastic versions can later test robustness under X1 conditions.

---

## 35. World-Family Independence

The world generator must not depend on UNKNOWN's internal implementation.

It must not:

- inspect UNKNOWN's hypotheses;
- inspect UNKNOWN's representation;
- modify itself based on UNKNOWN's candidate;
- reveal evaluator annotations;
- expose condition labels for convenience.

The world produces environment behavior.

The evaluator separately determines whether UNKNOWN's behavior satisfies benchmark criteria.

---

## 36. Scientific Invariants

The world-family design must preserve these invariants.

- **Invariant 1 — Public/private separation**
  UNKNOWN cannot access private benchmark truth.

- **Invariant 2 — Stable interaction contract**
  Condition identity must not alter the diagnostic interface.

- **Invariant 3 — Representation independence**
  R1 must be defined before UNKNOWN's performance is observed.

- **Invariant 4 — Model-family separation**
  Model-family expansion must operate over the same R0 representation when testing whether R1 is necessary.

- **Invariant 5 — Parameter separation**
  P1 must remain solvable without representation change.

- **Invariant 6 — Non-identifiability distinction**
  N1 must not be mislabeled as R1 merely because the evidence is insufficient.

- **Invariant 7 — Noise distinction**
  X1 must not be mislabeled as systematic representation failure.

- **Invariant 8 — Structural novelty**
  Transfer must vary structure rather than merely random seeds.

- **Invariant 9 — No shortcut condition encoding**
  Superficial distributions must not directly identify condition class.

- **Invariant 10 — Reproducibility**
  The same declared experiment configuration and seed must reproduce the same benchmark world and trajectory, subject to documented stochastic behavior.

## 38. Smallest Scientifically Useful Architecture

The current research decision is:

**Core:**
one typed relational dynamical world family

**Core conditions:**
R0 / P1 / M1 / R1 / N1 / X1

**Primary R1 construction:**
representation collision under fixed R0

**Validation:**
structurally distinct held-out world family

**Public interface:**
observe / act / intervene

**Private interface:**
ground-truth evaluator state

Additional world families should only be added when a concrete scientific requirement demonstrates that the existing family cannot provide adequate validation.

This avoids unnecessary benchmark inflation.

## 39. R1 Candidate Acceptance Requirements

A candidate representation extension should eventually satisfy:

1. It resolves an independently constructed R0 representation collision.
2. Its supporting evidence comes from public interaction.
3. Parameter changes cannot resolve the original collision.
4. Permitted model-family expansion cannot resolve the original collision.
5. It generates explicit predictions.
6. It exposes falsification conditions.
7. Intervention outcomes can provide additional evidence where applicable.
8. Its complexity can be evaluated.
9. Its provenance can be recorded.
10. Its transfer behavior can be tested.

Candidate acceptance and stopping remain governed by the D.4 extension acceptance contract.

## 41. Scientific Review

**Question**

Can a shared typed relational dynamical world family provide clean and reproducible conditions for distinguishing parameter failure, model-family failure, representation-level inadequacy, non-identifiability, stochastic variation, and transfer?

**Result**

PASS, subject to executable validation.

The strongest result is the constructive R1 formulation.

A clean R1 condition is not defined by the absence of a named feature.

It is defined by a representation collision:

```text
R0(H1) = R0(H2)
```

while:

```text
Y(H1) ≠ Y(H2)
```

and a valid extension produces:

```text
R1(H1) ≠ R1(H2)
```

This creates an explicit information-theoretic boundary between representation failure and downstream model failure.

**Important qualification**

A higher-order relation is only a candidate concrete implementation of this principle.

It is not itself proof of representation novelty.

The executable benchmark must establish expressibility under the complete R0 grammar.

---

## 42. Final D.5.2 Decision

- Adopt the typed relational dynamical world as the core benchmark world family.
- Adopt representation collision as the primary constructive criterion for R1.
- Use R0/P1/M1/R1/N1/X1 as core controlled conditions.
- Use structurally distinct held-out world-family instances for T1 transfer evaluation.
- Require the model-family recovery ladder to remain downstream of the fixed R0 representation boundary.
- Require public/private evaluator isolation, matched-world controls, intervention compatibility, and reproducibility.
- Do not define representation novelty by feature naming, relation arity, prediction improvement, or UNKNOWN's own performance.

Implementation remains deferred to later D.5 stages.
